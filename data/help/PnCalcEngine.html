Calculator Engine

Group: Filters/Expressions. Type: PnCalcEngine.

The arithmetic half of a four-function calculator: the part that turns a stream of keystrokes into a running display. Wire a Keypad into it and a Numeric seven-segment readout out of it, and the three nodes are a working pocket calculator — see examples/controls-and-logic/calculator.json.

Each incoming message is one keystroke, read from its data.key member. That is exactly what the Keypad emits, but anything writing the same member drives the engine just as well — an Injector for testing, or an MQTT feed from a physical keypad. A message carrying no usable data.key is ignored in silence, so a stray reading that wanders into the input cannot corrupt a half-typed sum.

What it emits

Every accepted keystroke emits the whole display, not just results, so the readout tracks the typing digit by digit the way a calculator's own display does.

MemberDescription
data.value The displayed number — what the seven-segment readout shows. Zero while the engine is in its error state.
data.output The display as text: 12. keeps the decimal point the user has typed but not yet filled in, and an errored engine reads Error.
data.success false once the calculation has errored, true otherwise.
The keys
KeyWhat it does
0…9 Appends a digit to the number being typed. A digit pressed straight after a result starts a new number rather than extending the result, and a leading zero is a placeholder — 0 then 5 is 5, not 05.
. Adds the decimal point, at most one per number. Pressed first, it starts 0..
+ - * / Folds the typed number into the accumulator under the previous operator, shows the running total, and holds the new operator for the operand still to come. So 2 + 3 + 4 = shows 5 after the second + and 9 after =.
= Completes the pending operation and shows the result. With no operator pending, 5 = is just 5.
C Clears everything — accumulator, pending operation, typed entry and any error.
CE Clears only the number being typed. The accumulator and the pending operator survive, so a mistyped operand can be retyped without restarting the sum.
Errors

Dividing by zero — or running a calculation off to infinity — latches an error. The node paints its error state, the display reads Error, and the emitted message carries data.success = false. While latched the engine ignores every key but C and emits nothing at all, which is the same dead end a real calculator's “E” is.

Settings
PropertyDescription
max-digits How many digits may be typed into one number before the entry stops accepting them — the digit count of the calculator being imitated (1–15, default 12). It caps typing only: a computed result is shown in full.
