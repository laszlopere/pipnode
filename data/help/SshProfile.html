SSH Login credentials

An SSH Login profile holds how to log into a remote host over SSH — the account, port, key and host-key policy — separately from where each node connects, which stays the node's own host field. Several nodes run a command on a remote machine over SSH (the Shell Command, df, free, lxc-ls and tmux-monitor shell nodes, and the host-monitoring CPU, Load, Memory, Temperature, Ambient, Disk IO, Net IO and Connections nodes); you fill the profile in once and any of them reference it by name from their SSH Login dropdown.

A node with no profile keeps the original behaviour: it logs in as the local desktop user using whatever SSH keys / agent are already available, trusting the host key on first sight. Choose a profile only when you need a different account, a non-standard port, a specific key, or a stricter host-key policy.

Before you start: make key login work

Pipnode runs commands non-interactively, so the connection must succeed without ever stopping to prompt. In practice that means key-based authentication (a key already loaded in your agent, or an identity file whose passphrase you supply below) rather than typing a password each time.

  1. Generate a key if you do not have one: ssh-keygen -t ed25519.
  2. Install the public half on the remote host: ssh-copy-id user@host.
  3. Sanity-check a non-interactive login from the machine running Pipnode: ssh -o BatchMode=yes user@host true && echo OK. If that prints OK without prompting, the nodes will connect cleanly.
Filling in the profile
FieldWhat goes in it
Username The remote login name (ssh -l). Leave empty to log in as the local desktop user, the way the SSH nodes do without a profile.
Port TCP port of the remote SSH server (ssh -p). Defaults to 22.
Identity file (private key) Optional. Absolute path, on the machine running Pipnode, to the private key to authenticate with (ssh -i). Leave blank to use your SSH agent or the default keys in ~/.ssh.
Key passphrase Optional. The passphrase that unlocks the identity file above. Stored in the host vault (mode 0600 in your config directory); never written into a worksheet file.
Password Optional. A password for password authentication, stored in the vault like the passphrase. Whether password auth is usable at all depends on the connection mode (a non-interactive login cannot prompt) — prefer key authentication; treat this field as a key passphrase unless the release notes say otherwise.
Host-key policy How to treat the remote host's key:
  • accept-new — trust the key the first time the host is seen and remember it; refuse only if it later changes. This is the default and matches how the SSH nodes behave without a profile.
  • strict — refuse to connect unless the host key is already known (no trust-on-first-use). Safest; requires you to have the key in ~/.ssh/known_hosts beforehand.
  • off — do not check the host key at all. This defeats the protection against man-in-the-middle interception — use it only on a trusted local network you control.

Once the profile is filled in, drop one of the SSH-capable nodes onto a worksheet, set its host field to the machine you want to reach, and pick this profile from its SSH Login dropdown.
