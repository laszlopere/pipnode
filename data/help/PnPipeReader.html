Pipe Reader

Group: Sources. Type: PnPipeReader.

Source that reads a named pipe (FIFO) and emits one message for every line another program writes into it. Pair it with the Pipe Writer to pass messages between two pipnode processes, or feed it from a shell script: 

echo "door opened" > /tmp/pipnode.in

The pipe is created when the path does not exist yet. A path that exists but is not a named pipe is refused (the file is left alone). Until a usable path is set the node shows the error state, painted red on the worksheet.

Reading never blocks pipnode. It does not matter whether a program has the other end open, and writers may connect and disconnect as often as they like: the node keeps listening. A line is emitted when its newline arrives; a trailing \r is dropped.

PropertyDescription
pipe-path Path of the named pipe to read. Created when missing. A leading ~ stands for your home directory.
format Output text (the default) or JSON message; see below.
Output text

Each line becomes one message: data.output is the line, data.value is the line's number when the whole line is a number (surrounding blanks allowed) and 0 otherwise, and data.success is true. The topic is the node's own.

JSON message

Each line is a whole message in one-line JSON — the envelope a Pipe Writer in JSON mode writes: 

{"type":"PnMessage","topic":"home/kitchen","id":"…","created":"…","data":{"value":21.5,"output":"21.5 C","success":true}}

Topic, id, creation time and the data bag are kept; the Pipe Reader becomes the message's source. A line with no "data" member is taken as the data bag itself, e.g. {"output":"hi","value":1}, and gets the node's topic. Blank lines are skipped. A line that is not valid JSON emits a message with data.success false and the parse error in data.output.

Errors

When the pipe cannot be created or opened, the node turns red and emits a success = false message whose output says why.
