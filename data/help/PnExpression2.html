Calculator 2

Group: Filters. Type: PnExpression2.

Multi-input variant of the Expression node. It evaluates an algebraic expression that can combine values from all of its input ports, e.g. value1 + value2 or (value1 - value2) / value2 * 100. The number of inputs is configurable from 2 to 8 via the inputs property, so an expression like value1 + value2 + value3 can fold several streams together.

The node remembers the last data.value seen on each input and binds it under that input’s name — value1 for input 1, value2 for input 2, and so on by default, or whatever you rename the inputs to. Because the values are remembered, both are available on every recompute even when only one input just fired. Any other numeric member of the message being processed is also bound, with the arriving input’s number appended — a sibling data.temp arriving on input 1 becomes temp1. Unlike the headline value, these sibling fields are not remembered across inputs: only the message actually being processed contributes them. The result is written to data.value of that message before it is forwarded.

PropertyDescription
inputs How many input ports the node has, from 2 to 8. Defaults to 2. Each input’s remembered value is bound as value1 … valueN (or the inputs’ renamed names).
expression The expression to evaluate. Defaults to value1 + value2.
Language
  • Numbers: 12, 12.3, .5.
  • Variables: each input’s remembered data.value under its input name (value1, value2, or a renamed input’s name), plus any other numeric member of the message being processed suffixed by the arriving input number, e.g. temp1, offset2.
  • Operators: + - * / with the usual precedence, parentheses for grouping, and unary minus.
  • Modulo: %, at the same level as * and /. The result takes the sign of the divisor, so -1 % 8 is 7, which is what wrapping an address or a counter wants. Works on fractions too (5.5 % 2 is 1.5).
  • Bitwise: & (and), | (or), ^ (exclusive or — not a power; that is pow(x, y)), << and >> (shifts), and unary ~ (not). Each operand is cut to its whole-number part and treated as a 64-bit signed integer; >> keeps the sign, so -8 >> 1 is -4. A value that is not a finite number, does not fit 64 bits, or a shift count outside 0–63 gives nan instead of an error. Results above 253 lose their lowest bits, because every value is carried as a double. Binding, tightest first: * / %, + -, << >>, &, ^, |, comparisons — so value & 1 == 1 means (value & 1) == 1. Example: the low 4 bits of an instruction word are value & 15 and the opcode above them is value >> 4 (there are no hex literals).
  • Comparisons: < > <= >= == !=. These bind looser than every other operator and evaluate to 1.0 (true) or 0.0 (false), e.g. value1 > value2.
  • Functions — trigonometry (angles in radians throughout): sin, cos, tan, their inverses asin, acos, atan, the reciprocals cot, sec, csc, and atan2(y, x) — the angle from the positive x axis to the point (x, y), using the signs of both to get the right quadrant, which atan(y/x) cannot. The reciprocals have poles and do not hide them: cot and csc are infinite at every multiple of pi, sec a quarter turn away.
  • Functions — angles: degrees(x) and radians(x). Every trig function above wants radians while every knob, dial and compass bearing is in degrees, so sin(radians(bearing)) is the shape most sheets want — and it is what bearing * pi / 180 was trying to say.
  • Functions — hyperbolic: sinh, cosh, tanh and the inverses asinh, acosh, atanh. cosh is the shape of a hanging cable; tanh is the S-curve that squashes any number into −1…1 without a comparison.
  • Functions — powers, roots and logarithms: sqrt, exp, pow(x, y) — x raised to the power y, and the only way to spell a power here, because ^ is bitwise exclusive-or (2 ^ 10 is 8, while pow(2, 10) is 1024); hypot(x, y) — sqrt(x*x + y*y) without the overflow the written-out form can suffer; log(x), which is the natural logarithm, log(x, base) for the logarithm to a base the sheet computes, and log10, which is the one most people mean when they write log.
  • Functions — rounding and sign: abs, floor, ceil, round, trunc, sign. round sends a half away from zero (round(0.5) is 1, round(-0.5) is -1, round(2.5) is 3) rather than to the nearest even number; trunc cuts toward zero, which is where it differs from floor on a negative (trunc(-1.7) is -1, floor(-1.7) is -2); and sign is -1, 0 or 1 — sign(0) is 0, because zero has no direction to report.
  • Functions — choosing and bounding: min(a, b) and max(a, b), which skip a nan operand rather than passing it on (min(nan, 3) is 3), and clamp(x, lo, hi), which holds x between the two bounds. clamp exists because min(max(x, lo), hi) is what people write instead and get the order wrong in; if the bounds are crossed (hi below lo) the lower one wins, and a nan value stays nan rather than becoming a bound.
  • Arguments are separated by commas, and a call with the wrong number of them is reported straight away, as a mistake in the expression — saying what the function actually takes, down to “1 or 2 arguments” for one like log that accepts either.
  • Constants: pi and e. They are not variables — an input member actually named pi is used in preference, so nothing you bind can clash with them.
  • Statements: several lines, one statement each (blank lines ignored). A line may be a bare expression or an assignment name = expr that binds name for later lines; data.value takes the last statement's value, and every assigned name is also written to the outgoing message as a numeric member.
  • Vectors: an input or sibling that is a $pnvector is handled as a bag of numbers — scalars broadcast over it, two vectors combine elementwise (the longer operand's surplus tail passes through unchanged), one-argument functions map over every element and two-argument ones follow the same rules an operator does, and a comparison reduces to a single 1.0/0.0 (true iff every element passes). See the Calculator node help for worked examples.

When there is no answer. A result mathematics does not define is a value here, not an error: sqrt(-1), acosh(0) and asin(2) are nan, log(0) and cot(0) are infinite, and each travels on down the wire like any other number — exactly as 1 / 0 always has. No function stops the sheet. That is deliberate: a gap in one sample of a curve should not take the whole plate down with it. 

expression: value1 + value2
expression: (value1 - value2) / value2 * 100
expression: sqrt(value1 * value1 + value2 * value2)

multi-line, binding an intermediate name and emitting it too:
    delta = value1 - value2
    delta / value2 * 100         (-> data.value, plus data.delta)
Output

On success the node sets data.value to the computed number, data.success to true, and data.output to the formatted result; any names assigned by the expression are added as numeric members too. If the expression cannot be parsed, or it references an input that has not produced a message yet (so e.g. value2 is still unknown), the message is still forwarded but flagged: data.success is set to false and the reason is placed in data.error and data.output, with data.value left unchanged.
