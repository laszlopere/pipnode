Topic Demux

Group: Filters/Gate. Type: PnTopicDemux.

Sorts messages by their topic. The node has one input and a configurable number of outputs, and every output has its own topic pattern. An arriving message is compared against the patterns of out1, out2, … in order and leaves, unchanged, by the first output whose pattern matches. A message that matches no pattern is dropped. An output with an empty pattern is unused and receives nothing.

One Topic Demux replaces a row of Filter nodes that each test the topic — for example to split everything an MQTT Source subscribed to with tele/plug/# into its sensor readings, state reports and the rest.

PatternMatches
tele/plug/SENSOR Exactly that topic.
tele/+/SENSOR MQTT wildcard: + matches exactly one topic level, so tele/plug1/SENSOR but not tele/a/b/SENSOR.
stat/# MQTT wildcard: a trailing # matches every remaining level, including none — stat, stat/plug/POWER, …
*SENSOR Glob, used whenever the pattern contains * or ?: * matches any run of characters (slashes included), ? one character.

Because the first match wins, a catch-all (# or *) on the last output collects every message the earlier outputs did not claim. Each output is labelled on the worksheet with its pattern (the end of it, when the pattern is long) and the value last sent through it.

PropertyDescription
outputs Number of outputs, 2–16. Default 4. The settings dialog shows one topic field per output. Lowering the count keeps the patterns of the removed outputs, so raising it again brings them back; wires on outputs that no longer exist stop carrying messages.
topics The patterns, one per output, stored as a JSON array of strings (["tele/+/SENSOR", "tele/#", "#"]). Edited through the topic fields of the settings dialog. Leading and trailing spaces are ignored.
