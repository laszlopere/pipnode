Text to Speech

Group: Sinks. Type: PnTts.

Speaks each incoming data.output string by piping it through a Linux text-to-speech program into the system audio output. Messages whose output member is missing or non-string are silently ignored.

The node supports several engines (Piper, eSpeak NG, eSpeak, Festival, Flite). When a new node is created, the first engine whose binary is found on $PATH is selected automatically. All engines remain selectable in the combo regardless of whether they are installed — picking an uninstalled one turns the node red with a warning icon and surfaces the missing-binary message in the “Status” row of the settings dialog.

PropertyDescription
engine Which TTS program to drive. One of piper, espeak-ng, espeak, festival, or flite. Defaults to the first one installed on the host.
model Voice used by the selected engine. Labelled “Voice” in the dialog. For Piper this is a path to an .onnx file under ~/.local/share/piper/voices; for the eSpeak family and Flite it is an engine-specific voice name; for engines with no voice selector (Festival) the dialog shows a single “Default” entry.
speed Playback rate multiplier in the range 0.5–2.0 (1.0 = engine default, >1 faster, <1 slower). Mapped to --length-scale for Piper, -s WPM for the eSpeak family, and --setf duration_stretch for Flite. Festival has no clean CLI rate knob and ignores the value.
sink PulseAudio output sink the speech is routed to. Labelled “Output” in the dialog. The combo lists every sink reported by pactl list sinks; the “Default” entry leaves PulseAudio's normal routing alone. For Piper this becomes a paplay -d argument; for every other engine it is delivered through the PULSE_SINK environment variable. Hosts without pactl / paplay behave as if “Default” was selected.
max-queue Maximum number of utterances allowed to wait while one is already being spoken. 0 drops new messages while the engine is busy (the original behaviour, useful when only the latest reading matters); -1 queues without limit (never drops, at the risk of a chatty upstream growing the backlog without bound); any positive value caps the backlog at that many items and drops anything arriving beyond, with a warning logged for each overflow. Defaults to 16, which is enough headroom for typical chat-shaped flows where a long LLM reply is still being read aloud when the next message lands. Pending utterances are spoken in arrival order; the per-source voice override (if any) is captured when the message is queued, so renaming the source while a clip is queued does not change the voice used for it.
per-source-voice When on (the default), the receive path hashes the incoming message's source-node name (the same string that ends up in the envelope's from field) and uses that hash modulo the engine's voice-list length to pick a voice automatically. Two different upstream nodes end up in two different voices — useful when a single TTS sink is fed by several speakers (e.g. an PnOllama reply on one wire and a PnMeshtastic message on another). The selection is deterministic, so the same speaker always gets the same voice across runs. Turn the switch off to force every utterance through the configured model. Engines without an enumerable voice list (Festival) and messages with no source fall back to model regardless of the switch state.
At least one of the supported TTS programs must be installed for this node to produce audio. Piper additionally requires paplay (from pulseaudio-utils) for playback; the other engines speak straight to PulseAudio themselves. See INSTALL for installation hints.
