Ethereum Address credentials

An Ethereum Address profile is a named account address: a unique name you choose (“Payout wallet”, “Cold storage”, “Miner 3”) paired with one 0x… address. Nodes that watch balances, payouts or transactions reference the profile by name, so a worksheet you share or commit names the wallet instead of hard-coding the address — and moving the worksheet to another machine is a matter of filling the profile in there.

No private keys

This profile holds a public address only. Pipnode has no key storage and cannot sign transactions, so there is no private-key or seed-phrase field, and nothing here is secret — an account address is public on-chain data. Anything Pipnode does with it is read-only: query a balance, follow transfers, report a payout. Never paste a private key or a seed phrase into the name field or anywhere else in Pipnode.

Filling in the profile
FieldWhat goes in it
Profile name The name you will pick from node drop-downs. Make it unique and descriptive — it is how you tell two addresses apart, and the only part of the pair you will read day to day.
Address The account address: 0x followed by 40 hexadecimal digits, e.g. 0xd8dA6BF26964aF9D7eEd9e03E53415D37aA96045. Required. Copy it from your wallet rather than typing it — a mistyped address is a different, usually non-existent, account.
Which chain?

None, and all of them. An address is derived from a key pair, not from a network, so the same 0x… identifies your account on Ethereum, PulseChain, Base, Arbitrum and every other EVM chain. The chain (and the RPC endpoint used to reach it) is chosen on the node, not here, so one profile serves every chain you watch that account on.

Checking an address

Mixed-case addresses carry an EIP-55 checksum: the pattern of upper- and lower-case letters encodes a hash of the address, which is what lets a wallet catch a typo. If you paste an address in and a node reports an empty or unexpected balance, compare it character by character against a block explorer before assuming the node is wrong.

Profiles live in ~/.config/pipnode/credentials.json (mode 0600), never in a saved worksheet. See Credentials and connection profiles for how profiles, primaries and per-node references work in general.
