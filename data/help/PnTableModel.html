Table Model

Group: Filters. Type: PnTableModel.

Filter that parses an ASCII / fixed-width text table out of the incoming message's data.output string and attaches the result to the same message as data.table before forwarding it on the output port. Designed for the output of column-aligned Unix tools (df, ps, ls -l, free, uptime, ...) so a downstream node can index a row's cell by column position rather than re-parse the text.

The emitted data.table has the shape: 

{
  "header": { "cells": [ { "text": "..." }, ... ] },    // optional
  "rows": [
    { "cells": [ { "text": "..." }, ... ] },
    ...
  ]
}

Each cell is a JSON object rather than a bare string so a future filter can decorate it with per-cell properties (colour, alignment, units, ...) without breaking the schema. The current Table Model only fills text; downstream consumers should ignore unknown cell members.

Column boundaries are detected in two passes. First, the first non-empty line is scanned for every byte offset at which a non-space character follows a space (or starts the line). Then each non-zero boundary is shifted left past any position where some data row carries a non-space character immediately before it, until the position just before the boundary is whitespace (or past end of line) in every row. That second pass keeps a right-aligned numeric column whose values are wider than the header label — e.g. df --output=source,fstype,size's 1K-blocks header with an 11-digit value below it — from bleeding into the previous column. All rows are then sliced at the adjusted offsets and each cell is whitespace-trimmed; lines shorter than the detected column count produce empty trailing cells so every row reports the same width.

The message is forwarded unchanged apart from the new data.table member: data.output, the envelope topic and id, and every other payload field survive intact, so chaining a Format or Debug Print after a Table Model still sees the original payload alongside the parsed table.

PropertyDescription
parse-header When true (default), the first non-empty line is emitted as data.table.header.cells and the remaining lines become data.table.rows. When false, the first line is still used to detect column positions but is emitted as the first row and no header member is produced.
