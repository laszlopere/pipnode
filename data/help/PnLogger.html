Logger

Group: Sinks. Type: PnLogger.

Sink that appends every received message to a log file on disk. It can rotate the file internally once it grows too large — no external logrotate tool is involved — and can write either buffered (fast) or flushed (durable).

Until a file-path is set the node shows the error state (painted red on the worksheet), since it has nowhere to write.

Every line has the same shape: an ISO-8601 local timestamp, then SUCCESS or FAILURE (taken from the message's data.success; falling back to data.value > 0.5), then the payload. In Lines mode the payload is the message's data.output text; in JSON mode it is the whole message envelope rendered as one-line compact JSON. 

2026-06-05T14:23:01 SUCCESS pump started
2026-06-05T14:23:05 FAILURE sensor timeout
2026-06-05T14:23:01 SUCCESS {"type":"PnMessage","from":"Sensor","topic":"t","id":"…","created":"…","data":{"value":1,"output":"ok","success":true}}
PropertyDescription
file-path Path of the file lines are appended to. Empty disables logging. Parent directories must already exist.
format Lines logs data.output; JSON logs the whole envelope as one compact JSON line. Both carry the timestamp + SUCCESS/FAILURE prefix.
logrotate When on (the default), the file is rotated once it reaches the maximum size, keeping a bounded number of numbered archives.
max-size-mb Rotate once the live log reaches this many megabytes. Only used when rotation is enabled.
max-files How many rotated archives (file.1 … file.N) to keep. On rotation the live file becomes file.1, older archives shift up, and anything past N is dropped. 0 keeps no history — the log is simply truncated. Only used when rotation is enabled.
flush Flush every line straight to disk. Off (the default) leaves writes buffered — faster, but the last lines may be lost on a crash.
