MQTT Broker credentials

A MQTT Broker profile holds the connection details every node that talks to an MQTT broker shares (the MQTT Source, MQTT Sink, Tasmota sensors and switches, …). You fill the profile in once and the nodes reference it by name, so the same worksheet moves between machines without leaking site-specific addresses or passwords into the file.

Picking a broker

Any MQTT-3.1.1 (or 5.0) broker is fine. The two most common choices on a small home setup are Eclipse Mosquitto (lightweight, ships in every Linux distribution) and EMQX (web dashboard, clustering).

Quick setup: Mosquitto on Linux
  1. Install the broker: sudo apt install mosquitto mosquitto-clients (Debian / Ubuntu) or sudo dnf install mosquitto (Fedora).
  2. Enable the service: sudo systemctl enable --now mosquitto.
  3. By default Mosquitto only listens on 127.0.0.1:1883 and refuses anonymous logins from the network. Edit /etc/mosquitto/conf.d/local.conf to add: 
    listener 1883
allow_anonymous false
password_file /etc/mosquitto/passwd
  4. Create a user / password: sudo mosquitto_passwd -c /etc/mosquitto/passwd username.
  5. Restart: sudo systemctl restart mosquitto.
  6. Sanity-check from the host running Pipnode: mosquitto_sub -h broker-host -u username -P password -t '#' -v. You should see messages flow in as other nodes publish.
TLS

For brokers reachable over the network it is strongly recommended to enable TLS. Point Mosquitto at a certificate (Let's Encrypt, an internal CA, or a self-signed one) with certfile / keyfile / cafile in /etc/mosquitto/conf.d/local.conf, raise a TLS listener on 8883, and use the ssl:// (or mqtts://) URL scheme in this profile.

A ssl:// / mqtts:// URL turns TLS on; the broker's certificate is then verified against your operating system's trust store. That is all a publicly-signed broker (Let's Encrypt and the like) needs. For a broker signed by a private or self-signed CA the system store will not contain the signer, so verification fails until you name the CA explicitly in the CA certificate file field below. The Client certificate / Client key pair enables mutual TLS, where the broker also authenticates this client by certificate. All of these are consulted only when the URL scheme selects TLS.

Filling in the profile
FieldWhat goes in it
Broker URL The broker address. Accepted forms: tcp://host[:port] for plain MQTT (port defaults to 1883), ssl://host[:port] for TLS (default 8883), and ws:// / wss:// for MQTT-over-WebSockets.
Username The login you created with mosquitto_passwd (or the equivalent for your broker). Leave empty for an anonymous broker.
Password The password for Username. Stored in the host vault (mode 0600 in your config directory); never written into a worksheet file.
Client ID Optional. Identifies this Pipnode instance to the broker so per- client retained-session state, last-will, and the broker's own audit log can pick it out. Pick something stable per machine (e.g. pipnode-livingroom); leaving it blank causes Pipnode to generate a random id on each connect.
CA certificate file (TLS) Optional. Absolute path, on the machine running Pipnode, to the PEM CA bundle that signed the broker's certificate. Needed only for a private / self-signed CA the system trust store does not already know. Leave blank to verify against the system store (the default for a publicly-signed broker). Used only with a TLS (ssl:// / mqtts://) URL.
Client certificate (mutual TLS) Optional. Path to this client's certificate, for brokers that require mutual TLS. Must be paired with Client key — supplying only one is ignored with a logged warning.
Client key (mutual TLS) Optional. Path to the private key for Client certificate.
Skip TLS verification (insecure) Off by default. When on, the broker's certificate is accepted even if it does not chain to a trusted CA or match the hostname. This defeats the protection TLS provides — use it only for local development against a self-signed broker, never in production. Each connect logs a warning while it is on.
Keep-alive (seconds) How often the client pings an idle broker so the link's health is known; the broker drops a client silent for 1.5× this. Defaults to 60 (leave blank or 0 for the default); capped at the protocol maximum of 65535.

Once the profile is filled in, drop an MQTT Source or MQTT Sink onto a worksheet and pick this profile from its Broker dropdown.
