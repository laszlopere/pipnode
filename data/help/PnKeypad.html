Keypad

Group: Sources. Type: PnKeypad.

A key pad on the worksheet. Clicking a key emits exactly one message naming the key that was pressed.

The node does no arithmetic and keeps no accumulator — it is an input device, not a calculator. What the keystrokes add up to is up to the graph downstream; the natural partner is the Calculator Engine, which accumulates the keystrokes, or the Calculator node, which evaluates an expression.

Layouts

The layout setting picks which keys the pad carries:

LayoutKeys
Basic Calculator (the default) The pocket-calculator pad on a 4×5 grid: ten digits, a decimal point, the four operators, =, and the two clear keys C and CE.
Decimal Keyboard The code-entry pad on a 3×4 grid: the ten digits in telephone order (1…3 on the top row, 0 at the bottom) plus the two extra keys * and #. No decimal point, no operators, no clear keys — a PIN has none.

On the decimal pad * and # emit the symbol kind rather than the operator the calculator pad's * (multiply) carries, so a flow can tell "the user pressed star" from "the user asked for a multiplication". It is the graph downstream that decides what they mean — # ending the entry is a convention, not something the node implements.

Switching layout resizes the node: the decimal pad is one column narrower and the same height, so the keys stay the same size on both.

The message a press emits
MemberDescription
data.key The key's machine-readable code: 0…9, and then whatever the layout adds — ., +, -, *, /, =, C, CE on the calculator pad, * and # on the decimal one.
data.kind The key's family: digit, point, operator, equals, clear, clear-entry or symbol. Lets a Filter or a Value Router split the stream without matching ten separate digit codes.
data.value The numeric value 0…9 — digit keys only. Absent on every other key, so a downstream numeric node consumes the digits and quietly ignores the rest.

The operator keys paint the typographic signs a calculator has on its buttons (×, ÷, −) but always emit the ASCII ones (*, /, -), so data.key can be concatenated straight into an expression string.

Using it

The keypad's body is the control itself, so a press lands on a key rather than lifting the node into the zoom overlay the way a graph or a table does. The header above the keys behaves like any other node header: click to select and drag, double-click to open the settings dialog. A click that lands in the gap between two keys presses neither.

A keypad emits only when a key is pressed. Unlike the Knob and the Switch it has no state to report, so a freshly-loaded worksheet stays quiet until the user actually presses something.

Settings
PropertyDescription
layout Which keys the pad carries — Basic Calculator or Decimal Keyboard, see above.
background-color Fill colour of the keypad's case — the panel the keys sit on.
key-color Face colour of the digit, decimal-point and clear keys.
accent-color Face colour of the keys the pad picks out in a second colour: the operators and = on the calculator pad, * and # on the decimal keyboard.
text-color Colour of the key legends.
