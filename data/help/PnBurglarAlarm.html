Burglar Alarm

Group: Controllers. Type: PnBurglarAlarm.

The panel of an intruder alarm: the box on the hall wall that watches four zones, counts the exit and entry delays, and decides when the siren goes off. It is to a Keypad what the Calculator Engine is — the state machine behind the keys — only with five inputs and five outputs instead of one each, because an alarm panel has more than one thing to say.

A working panel is five nodes: a Keypad on its Decimal Keyboard layout into keypad, four sensors into the zones, a Matrix57 character LCD on display, an LED (or a Tasmota relay) on alarm, and whatever you like on speech and sms. See examples/controls-and-logic/burglar-alarm.json.

Inputs
InputWhat arrives on it
keypad One keystroke per message, read from data.key — exactly what the Keypad emits. Digits build the code, # submits it, * rubs out what has been typed. A message with no data.key but a data.output string is taken as a whole code submitted at once, so an MQTT feed or a Text node can arm and disarm the panel remotely. Anything else on this input is ignored in silence, so a stray reading cannot rub out a half-typed code.
delayed The entry/exit route — the front door. Tripping it while armed starts the entry delay instead of the siren, giving whoever came in time to type the code.
zone 1…zone 3 Instant zones. Tripping one while armed sounds the siren at once.

A zone message carrying a numeric data.value sets that zone's held state the usual way (> 0.5 is open) — a door or window contact. A message with no numeric value is a momentary trip that leaves the zone closed — a PIR that only ever fires on motion. The difference matters when arming: a held-open instant zone stops the panel arming, a PIR that fired an hour ago does not.

The zones are named by their input names. Rename an input on the node's Inputs tab and the zone is renamed everywhere it is announced — the readout, the spoken sentence and the sms all read “Kitchen window” instead of “zone 1”.

Outputs
OutputWhat leaves by it
alarm The siren. data.value is 1.0 while it sounds and 0.0 when it does not, so it drives an LED, a Tasmota relay or anything else that reads the boolean encoding. data.output reads ALARM: <zone> or OK, and data.cause carries the zone name on its own. Written only when the siren actually changes.
display The panel's readout as text in data.output, two to four newline-separated lines — meant for a Matrix57 character LCD set to the same line count. data.value carries the running countdown in seconds (0 when nothing is counting), so a Numeric on the same wire shows the seconds. Written on every event and once a second while a delay runs.
armed data.value 1.0 once the system is armed — including while it is in entry delay or in alarm — and 0.0 while it is disarmed or still counting the exit delay. data.output reads ARMED or DISARMED. Written only on a change.
speech One short spoken sentence per event in data.output, for a Text to Speech node: “System armed.”, “Entry delay. Enter your code.”, “Alarm! Front door.”
sms One longer written sentence per important event, for a Meshtastic node or any other text sink. Alarms and their clearing always go out; arming and disarming do too only when sms-on-arming is set, because a radio message per arming is a lot of radio.

Every emitted message also carries data.state — disarmed, exit, armed, entry or alarm — so a Value Router or a Filter downstream can split the stream without parsing the text. On the speech and sms outputs the same state rides in data.value as its number (0…4).

The state machine
StateWhat happens in it
disarmed A valid code arms the panel — but only when no instant zone is held open; otherwise the readout says NOT READY and names what is open. The delayed zone is allowed to be open: that is the door being walked out of. Zones are still watched, so the readout always says what is open and why arming was refused.
exit Counting down to armed. Zones are ignored — walking through the hall on the way out is not a burglary. A valid code cancels.
armed The delayed zone starts the entry delay; any instant zone goes straight to alarm. A zone left open during the exit delay is re-read at the moment arming bites, so a window left open trips then rather than being forgotten.
entry Counting down to the siren. A valid code disarms. An instant zone does not wait for the count — whoever came in walked past the keypad.
alarm The siren sounds for siren-time seconds and then cuts off, the way a bell box must. The panel stays in alarm, remembering what tripped it, until a valid code disarms it, and paints itself red on the worksheet for as long as it does. A second zone tripping updates the named cause and restarts the siren, but does not send a second sms.

The state is not saved with the worksheet: a reloaded worksheet comes up disarmed, the only safe assumption about a house nobody was watching. On load the node announces that once — display, armed = 0 and alarm = 0 — so a wired LCD is not left blank and a wired siren is explicitly told to be quiet. It stays silent on the speech and sms outputs, which would otherwise talk to the room every time the worksheet is opened.

The keys
KeyWhat it does
0…9 Appends a digit to the code being typed, up to twelve. The readout shows it masked as stars.
# or = Submits what has been typed. # is the Decimal pad's enter key and = the calculator pad's, so either Keypad layout drives the panel.
*, C or CE Rubs out what has been typed and changes nothing else.

A wrong code puts WRONG CODE on the readout and says “Wrong code.” That is a beep, not a latch: the next keystroke clears it and the code that follows is judged on its own.

The readout

Four lines are built, of which the first display-lines are emitted — set that to the line count of the LCD it feeds.

LineWhat it shows
1 The banner: READY, NOT READY, EXIT 25, ARMED, ENTRY 20 or *** ALARM ***.
2 The detail: which zones are open, Leave now, All secure, Enter code, or the zone that tripped the alarm. A complaint (WRONG CODE, NOT READY) takes this line until the next keystroke.
3 The zone map — Zones .... with an open zone showing its marker (D for the delayed one, then 1, 2, 3) instead of a dot. So Zones D.2. is the front door and zone 2 open.
4 The code being typed, masked: Code: ****.

On a two-line panel there is no room for lines 3 and 4, so the masked code takes the detail line while it is being typed — which is what a two-line panel does.

Settings
PropertyDescription
code The code that arms and disarms the panel (default 1234). Leave it empty for a panel with no code at all, where a bare # arms and disarms. It is stored in the worksheet as plain text — this is a demonstration panel, not a certified one.
exit-delay Seconds between a valid code being accepted and the system actually arming — the time to walk out of the door (0–600, default 30). Zero arms immediately.
entry-delay Seconds between the delayed zone tripping and the siren — the time to reach the keypad (0–600, default 30). Zero makes the delayed zone behave like an instant one.
siren-time Seconds the siren sounds before it cuts off (0–3600, default 180). The panel stays in alarm until a valid code is typed. Zero means no cut-off: it rings until disarmed.
display-lines How many lines the display output carries (2–4, default 2). Two gives the state and one line of detail; three adds the zone map; four adds the code being typed on a line of its own.
sms-on-arming Also send an sms message every time the system is armed or disarmed. Off by default: alarms and their clearing always go out.
