Network I/O

Group: Host monitoring. Type: PnNetIo.

Auto-triggered probe that samples /proc/net/dev every period seconds and emits the live network-traffic volume (RX + TX bytes per second — not packet count) as data.value in the byte multiple chosen by the unit property — one of B/sec, KByte/sec, MByte/sec, or GByte/sec (decimal, 1 KByte = 1000 bytes). The default is MByte/sec — gigabit ethernet saturates around 125 MByte/sec, so the figure lands in a readable 0.x — 100.x range without truncating to all-zeros the way GByte/sec would on a 1 GbE host or overflowing the field the way KByte/sec would on a real workload. The figure is computed as the per-second delta of the kernel's cumulative byte counters between two consecutive ticks, so the first sample after construction (or after a hostname / interface change) carries value = 0 and a "warming up" note in data.output: a real reading needs two samples.

Note that network throughput is conventionally reported in bits per second (Mbps, Gbps) by switches and link-layer tools, while host-side tools that read /proc/net/dev report bytes per second. This node follows the byte convention to stay symmetric with Disk I/O and to match the underlying kernel counter; a downstream filter that prefers the bits-per-second convention can multiply by 8.

The sample comes from /proc/net/dev directly when hostname is empty or "localhost"; any other value is treated as a remote host and the file is fetched over passwordless SSH (ssh -o BatchMode=yes … hostname cat /proc/net/dev) on a worker thread, so an unreachable target cannot freeze the GUI.

interface picks which row to measure. An empty string (the default) sums across every non-loopback interface in the file — the lo row is always skipped on the all-interfaces path so localhost-loop traffic does not inflate the figure. A concrete value ("eth0", "wlan0", "enp86s0", "docker0", …) restricts the reading to that one interface.

The emitted message carries data.value (RX + TX throughput in the configured unit), data.rx, data.tx (the two halves of the sum, same unit), data.unit (the short string matching the chosen unit property), data.interface (the interface(s) that contributed: a single name, an empty string when no non-loopback row was found, or a "+"-joined list when the all-interfaces path summed several), data.host, data.success, and data.output (a one-line human summary — either the throughput figure broken into its rx/tx halves or the failure reason). When the SSH probe fails the remote stderr or the spawn error message is folded into data.output so a downstream Debug Print shows the user what went wrong; when the file was read but no row matched the configured interface, data.output explains that explicitly.

PropertyDescription
hostname Host whose /proc/net/dev to read. Defaults to "localhost"; an empty string is treated the same. Any other value is used as the SSH target — passwordless authentication must already be set up (BatchMode=yes is forced so the probe never prompts for a password). Changing this property mid-flight discards the previous sample so the next emitted value is the "warming up" zero rather than a spurious cross-host delta.
interface Network-interface name to measure ("eth0", "wlan0", "enp86s0", "docker0", …). An empty string (the default) sums across every non-loopback row of /proc/net/dev; the loopback row ("lo") is always skipped on the all-interfaces path. Changing this property mid-flight discards the previous sample (same reason as for hostname).
unit Output unit for data.value: B/sec, KByte/sec, MByte/sec, or GByte/sec (decimal multiples). The default is MByte/sec. The chosen short string is also emitted on data.unit so a downstream Graph axis label can pick it up verbatim. Changing this property does not invalidate the previous sample — the bytes/sec computation is the same, only the divisor differs.
period Seconds between samples. The default of 2 s keeps the per-tick delta well above any rounding noise while still feeling responsive in a downstream Graph.
