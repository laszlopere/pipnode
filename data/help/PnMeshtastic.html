Meshtastic

Group: Network. Type: PnMeshtastic.

Bidirectional bridge between the message graph and a USB-attached Meshtastic LoRa device. Speaks the device's framed-protobuf serial protocol natively in C — no helper subprocess — so the connection is held open for the lifetime of the node and incoming text packets land on the output port the moment they arrive. Outgoing messages received on the input port are sent on the configured channel as TEXT_MESSAGE_APP packets.

A single worker thread per node owns the serial fd, runs the configuration handshake on start-up to learn the device's channel list and node-name table, and then alternates between reading inbound frames and draining the outbound queue fed by the input port. Changing the device or channel property restarts the worker; toggling the node's disabled flag stops and restarts it cleanly.

Each inbound text packet is emitted as a message with topic: "meshtastic" and the following data-bag members: data.output (the message text), data.from_node_id (sender as !aabbccdd hex id), data.from_long_name (sender's display name from the node table, falling back to the hex id), data.channel_index, data.channel_name, data.packet_id, data.rx_time, data.hop_limit, data.hop_start, data.broadcast, and data.success = true. On a connection error a single message with data.success = false and data.error = "…" is emitted before the worker exits.

On the input port, data.output is read as the message text to send (same convention as Text to Speech and Sound). Other fields are ignored. Messages without a data.output string are dropped silently.

Accessing /dev/tty* typically requires the user to be in the dialout group on Debian/Ubuntu (or uucp on some distributions); otherwise the worker emits an EACCES error. The settings dialog's device combobox lists devices whose USB vendor/product IDs match the known-hardware table (Heltec V3, Tracker variants, SenseCAP); a device that isn't recognised but does present a working serial port can still be used by typing its path.

Below the two property rows the dialog shows a Status line that mirrors the worker's runtime state. While the worker is opening the port and running the configuration handshake the line turns red and reads Device /dev/ttyUSB0 is busy.; once the handshake completes and the local NodeInfo arrives, it switches to HELTEC_V3 is ready. (or whichever HardwareModel the device reports — the symbolic name matches the table the pip-mesh CLI prints). If the configured port cannot be opened for any other reason (the cable was unplugged before the worksheet loaded, the kernel never enumerated the device, the user lacks dialout group membership, the device disappeared mid-stream and the read loop saw a hangup) the line shows Device /dev/ttyUSB0: No such file or directory or the equivalent errno text in red, and the node body switches to the warning ❗ visual until the user picks a different device or the worker successfully re-opens the port. The line clears when no device is selected.

PropertyDescription
device Serial-port path of the USB-attached Meshtastic device (e.g. /dev/ttyUSB0, /dev/ttyACM0). Empty leaves the node disconnected.
channel Case-sensitive name of the channel to send on (e.g. LongFast). Empty falls back to the primary channel (index 0). The dialog combobox is populated from the device's live configuration.
