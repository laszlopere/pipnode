Query

Group: Filters. Type: PnQuery.

Runs every received message through a configurable JMESPath expression and writes the result back onto the message before forwarding it. The output is always well formed: a parse error, a type error, or a query that matches nothing still emits a message — failures surface as a data.error string and a JSON-null result, never as a dropped message.

PropertyDescription
expression The JMESPath query. Empty produces a JSON-null result.
result-field Where to put the result. A non-empty name (default result) writes to that member of the data bag, leaving the surrounding members in place. The empty string or the literal data mean the result is the new data bag — existing members are dropped, and a non-object result is wrapped under a value key so the bag stays well formed.
source-field Slash-separated path into the incoming message that the query runs against. Empty (the default) queries the whole message root, where topic, id, created, and data are visible as top-level members.

The supported JMESPath subset covers identifier paths (a.b.c, "quoted-id"), index and slice ([0], [-1], [1:5:2]), projections ([*], .*, [?expr], []), multi-select ({k: a, k2: b}, [a, b]), pipes (|), comparisons (== != < <= > >=), boolean logic (&& || !), expression references (&expr), raw literals (`null`, `true`, `123`, `"str"`), single-quoted string literals ('str'), and the current-node operator (@).

Built-in functions: length, type, keys, values, contains, starts_with, ends_with, to_string, to_number, to_array, abs, ceil, floor, sum, avg, max, min, max_by, min_by, sort, sort_by, reverse, not_null, merge, join, map. 

expression:    data.transactions[?value != `"0x0"`].hash
result-field:  hashes

expression:    {block: data.number, count: length(data.transactions)}
result-field:  summary

expression:    sort_by(data.logs, &blockNumber) | [-1]
result-field:  latest_log
