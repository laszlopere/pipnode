Notify

Group: Sinks. Type: PnNotify.

Shows a desktop notification whenever a message arrives. The notification is delivered over D-Bus to the freedesktop org.freedesktop.Notifications service on the session bus — the same protocol libnotify, notify-send, and GNotification use, so any desktop environment that displays standard notification bubbles (GNOME, KDE, XFCE, Cinnamon, MATE, dunst, mako, …) shows them without any extra configuration.

Summary and body are template strings; ${path/to/field} placeholders expand against the incoming message's lookup root (the same root PnFormat uses, carrying topic, id, created, and every member of the data bag). For example ${topic} expands to the message topic, and ${data/output} reaches the data bag's output member. Unknown paths render as the empty string.

PropertyDescription
summary Notification title template. Defaults to ${topic} so a typical pipeline carries the source topic into the bubble header.
body Notification body template. Defaults to ${data/output} to pair naturally with upstream nodes (PnFormat, PnRewrite) that write into data.output.
icon Freedesktop icon name (e.g. dialog-information, dialog-warning, dialog-error, mail-message-new) or an absolute path to an image file. Empty hides the icon.
app-name Application name the daemon reports next to the bubble on desktops that show it. Defaults to pipnode.
urgency Freedesktop urgency hint: low, normal, or critical. Critical bubbles typically bypass the do-not-disturb filter and stay on screen until dismissed.
timeout-ms Bubble expire timeout in milliseconds. -1 (the default) lets the notification daemon pick; 0 means "never expires" — the user must dismiss it.
replace When on (the default), every new notification from this node replaces the previous one in place rather than stacking a fresh bubble. Useful for fast-firing sources where a tray full of duplicates would be noise.
This node depends on a running freedesktop notification daemon on the session bus. Every mainstream Linux desktop ships one; on a headless host without a session bus the node logs a warning and drops the notification.
No bubbles appearing on XFCE? If the daemon is xfce4-notifyd and Do Not Disturb is on, every call is accepted (a notification id is returned) but the bubble is silently suppressed — so the node looks like it is misbehaving even though the wire call succeeded. Check and disable DND with: 
xfconf-query -c xfce4-notifyd -p /do-not-disturb
xfconf-query -c xfce4-notifyd -p /do-not-disturb -s false
Setting urgency to critical on the node also bypasses DND on most daemons, so a single high-priority alert can still come through without flipping the global switch.
