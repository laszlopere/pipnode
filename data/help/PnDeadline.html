Deadline

Group: Filters. Type: PnDeadline.

Reports how far away a fixed point in time is. Each incoming message must carry a numeric value holding the current instant as a Unix epoch — exactly what the Clock node emits. The node interprets its configured target wall-clock time in the selected timezone, converts it to a Unix epoch, and forwards the message with value rewritten to the seconds remaining, target − now. The value counts down to 0 at the target and keeps going negative afterwards, so a downstream node can detect “passed” with value ≤ 0. All other members of the message are passed through untouched.

The timezone is a fixed-offset abbreviation with a spelled-out name (e.g. CET — Central European Time), never a city. Daylight-saving variants are listed as their own offsets (CET vs CEST), so no daylight-saving guessing takes place. The default is Not Set: with no fixed zone selected the node reads the incoming message's timezone member as a bare abbreviation (which the Clock node emits as the local zone, e.g. CEST) and interprets the target in that zone. An unknown, missing or ambiguous abbreviation falls back to GMT (UTC+0).

SettingDescription
target Target instant as a yyyy-mm-dd hh:MM:ss wall-clock string. Pre-filled with the current date and time. An unparseable value makes the node emit nothing.
timezone The timezone the target is expressed in, chosen from a list of abbreviations and names. Not Set (the default) defers to the incoming message's timezone member; an unknown or missing abbreviation falls back to GMT.
