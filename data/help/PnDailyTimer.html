Daily Timer

Group: Sources. Type: PnDailyTimer.

A weekly on/off schedule. Open the node's settings dialog and build a list of intervals — each one a day of the week (or Every day), an on time and an off time. The node watches the local wall clock and emits a message with data.value = 1.0 when the time enters any interval, and data.value = 0.0 when it leaves the last one. data.success mirrors the same state as a boolean and data.output carries the word on or off, so the tick plugs straight into a Tasmota relay, an LED, a Debug view or a text-to-speech sink.

Only the transitions are emitted. The node polls once a second but stays silent while the computed state is unchanged, so a downstream relay sees one message per switch-over rather than one per second.

The very first poll after the worksheet loads always emits, whichever state it finds. Opening a worksheet at 08:00 with an 07:00 – 09:00 interval leaves the heating on; opening it at 10:00 leaves it off. Without that announce the relay would sit in whatever state it happened to be in until the next edge came around — possibly the next morning. Editing the schedule re-announces for the same reason: the rules changed, so the verdict is re-sent even if it happens to be the same one.

Interval bounds are half-open: the timer switches on during the on minute and off during the off minute. Back-to-back intervals (06:00 – 08:00 followed by 08:00 – 10:00) therefore neither overlap nor leave a one-minute gap where the relay drops out. Overlapping intervals union rather than fight — the timer is on whenever any interval matches.

An off time at or before its on time wraps past midnight into the following day: a Friday 22:00 – 06:00 interval is in force on Friday evening and through Saturday morning, ending at Saturday's 06:00. An interval whose two times are equal is degenerate — a zero-length window and an all-day window are equally defensible readings of it, so neither is guessed at and the row is ignored.

The state is recomputed from the clock on every poll rather than tracked incrementally, so a suspend/resume, an NTP step or a daylight- saving changeover lands the node on the state its schedule implies for the new time, instead of on whatever the missed edges would have left behind.

PropertyDescription
schedule JSON array of {day, on_hour, on_minute, off_hour, off_minute} intervals, normally edited through the dialog's row editor. day is 1 (Monday) through 7 (Sunday), or -1 for every day. A hand-edited file with an out-of-range day falls back to every day; out-of-range times clamp.
period Inherited poll interval in seconds (default 1). The schedule has minute resolution, so this only controls how promptly a transition is noticed.
