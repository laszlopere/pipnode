Figure

Group: Sinks. Type: PnFigure.

Sink that draws a textbook-style figure — a lever, a lens, a pendulum, a field line — from a small drawing program, one verb per line. The program's arguments are expressions in the same language the Calculator 2 node uses, and the node's inputs are variables in it, so the drawing follows the values wired into it: turn a knob and the beam tilts. When an input is a vector, the figure becomes a film and plays it (see Animation).

If what you want is a chart of numbers rather than a picture of a thing, use a Graph (values over time), a Plot (one vector as a dataset) or an Oscilloscope (a trace) instead: they draw axes, scales and legends for you, and a Figure draws only what its program says.

This page is also the specification of the drawing language; there is no other.

A first figure
view -60, -25, 60, 35
color "#202020"
width 2

# the beam, tilted by the input angle (radians)
dx = 50 * cos(value1)
dy = 50 * sin(value1)
line -dx, -dy, dx, dy

# the fulcrum: grey, outlined in the stroke colour
fill "grey"
poly 0, -2, -8, -14, 8, -14
nofill

text -dx, -dy + 6, "A"
text  dx,  dy + 6, "B"
text 0, 27, "%.1f deg", degrees(value1)

Wire a Knob into the node and the lever tilts as the knob turns, with the angle printed above it. With nothing wired, value1 is 0 and the beam lies flat — an unwired figure still draws.

Coordinates

Y points up. This is a physics figure, not a screen: view xmin, ymin, xmax, ymax declares the window in your own units, with ymin at the bottom. The window is fitted into the card preserving its aspect ratio and centred, and the space left over (the letterbox bars) is filled with the background colour. Without a view statement the window is 0, 0, 100, 100. The window is fixed and never fitted to what is drawn, so a moving drawing does not make the figure zoom. Reversed bounds are allowed and flip that axis.

Every length — line widths, radii, dash lengths, font sizes — is in the same units and scales with the drawing, so the zoom overlay enlarges a figure like a photograph. A stroke is never thinner than about three quarters of a pixel, except width 0, which is always a hairline.

The language
  • One statement per line: a verb followed by its arguments separated by commas, or an assignment name = expression. Blank lines and indentation are free; indent to group a figure into its parts.
  • Comments start with # and run to the end of the line. A # inside quotes is a character.
  • Continuation: a line whose last character (before any comment) is a comma continues on the next line — which is how a long poly is written.
  • Quoted means literal, unquoted means expression, in every argument position: color "#202020", dash "dot", text x, y, "A". Strings take \", \\ and \n.
  • Verbs are case-insensitive (Line is line); variable names are case-sensitive.
  • Assignment: if the first word is followed by = (and not ==), the line is an assignment and binds a variable for the lines below it. A variable may legally be called line; please don't.
  • Every verb takes the arguments its table row shows, a fixed number or a list in pairs, some of them optional ones in brackets; the count is checked before anything is drawn.
  • Blocks — repeat, if, with, origin and def — run to a line of their own that says end, and one end closes the innermost block still open.
Pen state

Settings persist until changed, as on a pen plotter, and each is reset to its default at the start of every frame. <colour> is either one quoted literal — "#rgb", "#rrggbb", "#rrggbbaa", "rgb(r, g, b)", "rgba(…)" or a name: black, white, red, green, blue, yellow, cyan, magenta, grey/gray, orange, brown, transparent — or three or four expressions r, g, b [, a] from 0 to 1, which is how a colour follows a value.

VerbArgumentsEffect (default)
viewxmin, ymin, xmax, ymax The user-unit window (0, 0, 100, 100). Applies to what follows it.
color<colour> Stroke colour (black).
fill<colour> Fill colour, and turns filling on (off).
nofill Turns filling off.
widthw Stroke width in user units (1); 0 is a device hairline.
dash"style" [, scale] "solid" (default), "dot", "dash" or "dashdot", lengths multiplied by the optional scale.
fontsize Text size in user units (5).
align"h" [, "v"] Text anchoring: "left", "centre" (or "center"), "right"; and "top", "middle", "baseline", "bottom". Default centre, middle — text x, y, "A" labels the point.
arrowheadlength, width The head of every arrow and head (see Arrows): tip to base, and across the base, in user units (3, 2.4).
anglea Turns every label that follows by a degrees counter-clockwise about its anchor (0, upright) — a label along an axis or a ray (see Rotated labels).

A shape drawn with filling on is filled and then outlined in the stroke colour, which is why color and fill are separate: a grey triangle with a dark outline is one of each. Lines have round caps and round joins.

Settings for a moment: with
circle 2.8, 22, 0.6  with fill "#2e8b57"
text 45, 36.5, "refused"  with color "#c0392b", font 3.8

with color "#c0392b", width 0.3, dash "dot"
  line r, 22, r, 14.5
  circle r, 13.9, 0.6
end

A drawing statement followed by with and a list of pen settings is drawn with those settings, and the pen gets back what it had straight after it: no nofill, no second color to put things back. A line that begins with with does the same for every line down to its end. The list is the pen verbs above, separated by commas and written as they are on a line of their own: with color 1, 0, 0, width 2 is two settings, because each new one starts with its verb. view is not a pen setting, and neither is the pen's position: a view set inside a block stays, and a lineto chain runs on out of one. Blocks nest, inside and around the other blocks, and each end gives back what its own with found. with is a keyword, so it cannot name a variable.

Geometry

linex1, y1, x2, y2 A segment; leaves the pen at its second point.

arcx, y, r, a0, a1 An arc from angle a0 to a1 in degrees, counter-clockwise when a1 > a0, so arc 0, 0, 10, 90, 0 is a clockwise quarter.
rectx, y, w, h A rectangle from its lower-left corner; a negative w or h extends the other way.
polyx1, y1, x2, y2, x3, y3, … A closed polygon, at least three points.
pathx1, y1, x2, y2, x3, y3, … An open polyline, at least three points; never filled.

arrowx1, y1, x2, y2 A line ending in a solid head whose tip is at the second point — a force, a velocity, a pointer.

hatchx1, y1, x2, y2, spacing [, depth] A surface that is solid on one side — a wall, a ceiling, the ground: the line, and short slanted strokes along it (see Hatching).

anglemarkx, y, r, a0, a1 [, "format", expr, …] The arc that marks an angle, drawn as arc draws it, and a label just outside it on the bisector (see Angle marks).

Only move, rmove, lineto, rline and line move the pen; it starts every frame at (0, 0). The shapes are placed absolutely and leave it where it was.

Arrows
arrowhead 3.4, 3.4
arrow 0, 0, 0, -26 * m / mmax  with color "#3a5a9b"

line xi, yi, 0, 0
head xi, yi, xi / 2, yi / 2

arrow x1, y1, x2, y2 draws a line from the first point with a head on the second, the tip exactly on the point, and the line stops at the head's base so a thick one cannot poke through the tip. head draws the head alone: the first point only tells it which way to point, so a direction mark halfway along a ray is the ray's own start and its middle. Neither moves the pen.

A head is always a solid triangle in the stroke colour: it ignores fill and nofill, is never dashed (a dashed arrow is a dashed line with a solid head) and is not outlined in the line's width, so a thick arrow keeps a sharp tip. Its size is the arrowhead setting, a pen setting like the others: set it once for the figure, or for one arrow with arrow … with arrowhead 5, 4. Being an expression, it can follow the line: with arrowhead 3 + w, 3 + w. An arrow shorter than its head shrinks the head to fit, keeping its shape, so an arrow drawn to scale never reaches back past its start — a force of nothing is nothing. A head never shrinks. An arrow whose two points are the same has no direction and is skipped, like a circle of radius zero.

Hatching
hatch -26, 0, 26, 0, 8        # a ceiling: strokes above
hatch 46, 0, -20, 0, 3, 1.2   # the ground: run right to left, strokes below

hatch x1, y1, x2, y2, spacing, depth draws the line from the first point to the second at the pen's width, and along it short strokes at half that width, spacing apart and centred on the line, as many as fit. Each stroke stands depth off the line on its left as it runs from the first point to the second — above a line drawn left to right — and leans 45° forward, the way it runs. A negative depth puts the strokes on the right instead, so the direction and the sign between them give all four ways a hatch can face and lean. Left out, depth is three quarters of the spacing. Like the other shapes, a hatch turns with origin axes and leaves the pen where it was. A hatch with no length, no spacing or no depth is skipped, and so is one that would need more than 1000 strokes.

Dimension lines
dimension xd, 0, xd, -h               # how far the hand moved
text xd + 2, -h / 2, "p"  with align "left", "middle"

dimension x1, y1, x2, y2, tick draws the line between the two points and, across each end, a tick tick long, square to the line and centred on it; left out, tick is 3. All three are drawn in the current pen. The label is a text of its own, since only the program knows which side of the line has room for it. A dimension line turns with origin axes and leaves the pen where it was; one between two equal points, or with a tick of no length, is skipped.

Curves
# a biconvex lens, 60 tall and 6 thick, its faces parabolas
curve 0, 30,   4, 10,   4, -10,   0, -30,
      -4, -10,   -4, 10,   0, 30

curve starts at its first point and then takes three points per segment: two control points and the end, which is where the next segment starts. A segment leaves its start heading for the first control point and arrives at its end coming from the second, the way a PostScript curveto or any drawing program's pen tool does; a curve whose control points are two thirds of the way from each end to the point where the two end tangents cross is exactly a parabola, which is how the lens above is drawn. A curve that ends exactly at its first point is an outline, and is filled and stroked like a poly; any other is a stroke only, like a path. The count of numbers must be 2 plus a multiple of 6. A curve turns with origin axes, stretches with the view like any other line, and leaves the pen where it was.

Angle marks
anglemark 0, 0, 12, -90, -90 + theta, "θ"
anglemark x, y, 8, 0, a, "%.0f°", a  with font 4

anglemark x, y, r, a0, a1 draws the arc arc x, y, r, a0, a1 would; with a label after it — a format and its values, exactly as a text takes them — it also writes the label on the bisector, just outside the arc, aligned so that it grows away from the arc whichever way the bisector points. The label is always upright, whatever angle and align say. A mark with no radius is skipped. Where the label must go somewhere cleverer — kept off a rod, say — draw the arc and a text of your own, as the pendulum plate does.

Axes
axes -40, -30, 80, 60, "t", "x"

axes x, y, xlen, ylen, "x name", "y name" draws two arrows from (x, y): one xlen along the x axis and one ylen along the y axis, a negative length pointing the other way, with heads the size of the arrowhead setting. Each name is written just past its arrow's tip, upright and aligned away from it, and either may be left out. A name is a label and not a format, so a per cent sign is %% as in a text. Ticks and scales are the program's to draw, with a repeat. Axes turn with origin and leave the pen where it was; an axis of no length skips the pair.

Rotated labels
text 20, 5, "F = %.0f N", F  with angle 30
text x, y, "ray"  with angle degrees(atan2(dy, dx)), align "left", "bottom"

Labels are upright unless the pen setting angle a turns them: each text after it is turned a degrees counter-clockwise about its anchor, and the alignment and the \n line stacking follow the turned baseline, so align "left", "bottom" puts a label just above a ray and reading along it. Like any setting it lasts until changed, so it is usually scoped with with. The angle is the drawing's, not the axes': inside an origin block a label stays upright, and one that should lie along the block's axes says so with the same angle the block was turned by — the beam balance's scales are printed with angle tilt inside origin px, py, tilt. Angles are measured as the plate shows them, so a view with reversed bounds does not mirror a label, and a stretched one lays it along the same slant as the line it labels.

Two angle conventions, on purpose. Verb arguments (arc, anglemark, origin, angle) are degrees, as in PostScript and on a protractor; sin, cos, atan2 and the rest of the expression functions work in radians. Convert with degrees(x) and radians(x).

Expressions and variables

Every unquoted argument is an expression in the calculator language — the operators, functions and constants are listed in the Calculator 2 page, and the Figure has exactly the same ones; only a comparison of a vector gives a different answer here (see Animation). The constants pi and e are there, and so are two-argument functions such as atan2(y, x), hypot, min, max, clamp and pow. ^ is exclusive-or, not a power: square with x * x or pow(x, 2).

The variables a program can read, in the order they are bound:

  1. the constants pi and e;
  2. each input's last data.value, under the input's name — value1 … valueN by default, or whatever the inputs are renamed to. Every input is remembered, so all of them are available on every repaint, not only the one that just fired. Other numeric members of the arriving message are bound too, with the input's number appended (data.temp on input 1 is temp1). Strings are never bound: a figure draws numbers;
  3. frame and t, when the figure is a film (Animation);
  4. anything still unbound is 0, so an unwired figure draws.

Earlier in that list wins: an input named t beats the animation's t, as any input beats the zero. Two more are bound while the program runs, and override whatever the name held: i inside a repeat block, and assignments, from the line that makes them onwards. Inside a shape (def) only its parameters, its own assignments and its own i are bound.

Repeating
repeat 11
  line i * 10, 0, i * 10, 3
end

repeat n … end runs the lines between them n times, with i counting 0, 1, 2 … — ticks along an axis, the slits of a grating, the teeth of a gear. The count is an expression. The block is shorthand for writing the lines out: pen settings and assignments carry from one pass to the next. A repeat cannot hold another repeat, not even through an if; a grid is one loop with floor(i / cols) and i % cols. A count below 1 or not a number skips the block, and a count above 1000 skips it rather than freezing the editor.

Choosing
if r > 2.05
  text 0, -57, "CAMERA"
elseif abs(r - 2) <= 0.05
  text 0, -57, "COPIER"
else
  text 0, -57, "PROJECTOR"
end

if c … end runs the lines between them only when c is not zero; a comparison is 1 when it holds and 0 when it does not, and an input carrying an on/off value (0 or 1) works as it is. Any number of elseif c clauses and one closing else may follow: the first clause whose condition holds runs, and no other. Like repeat, the block is not a scope — an assignment or a pen setting made in the branch that ran still stands after the end. An if nests anywhere: inside another if, inside a repeat (choosing per pass by i), or around one. A condition that is not a number (0 / 0, a division by zero) skips the whole block, the else too, the same way a bad repeat count does.

In a film, a condition that is a vector chooses frame by frame: if frame skips only frame 0, and if frame > 3 runs from frame 4 on. A comparison of a vector is itself a vector here, 1 in the frames where it holds and 0 in the others (see Animation).

Local axes: origin
origin px, py, tilt
  line -40, 0, 40, 0
  rect -3, -2, 6, 2
  circle 40, 0, 1.5
end

origin x, y, angle … end draws the lines between them on axes of their own: the point 0, 0 is at x, y, and the axes are turned counter-clockwise by angle degrees (0 when left out). A beam that tilts, a resistor on a slanting wire or a pendulum's arm is then drawn level, in its own numbers, instead of turning every point by hand with cos and sin. Blocks nest, each placed on the axes of the one around it, so the turns add up. The angle may be a vector: the axes turn frame by frame at no extra cost.

The axes are turned and moved, never scaled, so a radius, a width and a font size mean the same inside as outside. Circles stay circles and an arc's angles turn with the axes; a rect on axes turned by anything but a whole quarter is drawn as the tilted four-cornered shape it is. A label's anchor moves, but the label itself stays upright; to lay it along the axes, give it the block's own angle with with angle (see Rotated labels). origin changes where things are drawn and nothing else: pen settings made inside it stand after its end, and the pen is left where it was drawn to, so a lineto chain can run out of the block. The origin is in the window's units, so a view inside a block changes the window without moving the origin. An angle or position that is not a number skips the block.

Shapes of your own: def
def pulley x, y, r
  circle x, y, r
  point x, y with width 2
end

pulley 30, 60, 8
pulley 30, 20, 5 with color "grey"

def name p1, p2, … … end gives the lines between them a name, and from then on a line that starts with that name draws them, with the numbers after it as p1, p2 and the rest. A shape may take no parameters at all. Its name is spelled like a verb, so capitals do not matter, and cannot be a verb the language already has. A def draws nothing where it stands.

A shape reads only what it is given: its parameters, the names it assigns itself, and i inside a repeat of its own. An input, t, frame or a variable of the program is an error inside a shape — pass it in as a parameter. That is what lets a shape be copied from one figure into another and mean the same thing there. What a shape assigns stays in the shape: a variable of the same name outside it is left alone, and so is the i of a loop the shape is called from, which is why a shape with a loop in it may be called from a loop.

A call works like a with: pen settings the shape makes are given back at its end, and a call may carry a with list of its own. The pen position and the view carry on. Inside an origin block the shape is drawn on its axes, which is the way to turn one. A shape can use the shapes defined above it but not itself, a def must stand outside every block, and a shape cannot set the view. A parameter may be a vector: the shape then animates like anything else.

One walk of a program may run at most 200,000 statements, counting every pass of every loop and every line of every call; a figure that needs more shows an error instead of drawing.

Animation

When an input is a vector — from a Ramp, say — the figure becomes a film: frame k takes element k of every vector, and plain numbers are the same in every frame. The program is not rewritten per frame: arithmetic on vectors works element by element, so dx = 50 * cos(a) with a vector a simply makes dx a vector too, and a colour, a width, a view, a repeat count or an if condition (see Choosing) animates exactly like a coordinate.

  • How long. The film is as long as the shortest vector input the program reads, so every frame is drawn from real values of every input. (The arithmetic itself pads the other way: a * b of a 2-element and a 3-element vector is a 3-element vector whose last element is b's own — the figure shows two frames and never that third one.) An input the program does not read does not count, and an empty vector is an error.
  • frame and t. frame counts 0, 1, 2 … and t runs from 0 towards 1 over the film. In a loop, t stops one step short of 1 (with 4 frames: 0, .25, .5, .75), so a periodic figure such as sin(2 * pi * t) comes round without showing the same pose twice. Played once or ping-pong, the last frame is exactly t = 1 (0, .333, .667, 1), so the pose it holds or turns on is the true end. In a still both are 0.
  • A film with nothing wired. Set Frames on the Animation tab and the figure plays with no input at all, moved by t: 
    # Animation tab: frames 50, play-mode loop
view -50, -65, 50, 10

a = 0.6 * sin(2 * pi * t)
x =  50 * sin(a)
y = -50 * cos(a)

fill "grey"
rect -15, 0, 30, 3
nofill

width 0.5
dash "dash"
line 0, 0, 0, -58
dash "solid"

width 1
line 0, 0, x, y
fill "orange"
circle x, y, 5
    A turning wheel, with its spokes drawn by a loop: 
    # Animation tab: frames 100, play-mode loop
view -60, -60, 60, 60
width 1.5
circle 0, 0, 50

repeat 8
  a = 2 * pi * (i / 8 + t)
  line 0, 0, 50 * cos(a), 50 * sin(a)
end

fill "red"
circle 50 * cos(2 * pi * t), 50 * sin(2 * pi * t), 4
    Inside a repeat a vector is still a film, never a loop: a above is a vector over the film on every pass, while i is always a plain number.
  • Playing. New data, or an edited program, keeps the film playing from the frame it is on, so a knob on a pendulum's length changes the swing without restarting it. Only a film of a different length starts again from its first frame. The film plays only while an editor has its worksheet open; run without one, a figure uses no timer.
  • What it costs. The whole film is worked out once, when the program or an input changes, and each frame is then only read from it. So a film can afford a lot of arithmetic: a repeat loop can step a motion that has no formula forward in time, with a mask such as m = step(i, 4 * frame - 1) freezing each frame's copy of the state once it has taken its own share of steps. The double-pendulum example does this with a thousand steps. The price is paid on every change instead: turning a knob on such a figure works the whole film out again, which takes a moment. A repeat count or an if condition that is itself a vector is the exception — it gives each frame a different walk through the program, so that film is worked out frame by frame. A mask used as a number, such as m above, keeps the one walk.
  • Comparisons are per frame. A comparison of a vector compares element by element, so hot = s > 0 is a vector too: 1 in the frames where s is positive, 0 in the others, and width 1 + 2 * hot thickens a line only in those frames. Where two vectors of different lengths are compared, the elements past the shorter one are 0. This is the one place the Figure's arithmetic differs from the Calculator 2's, where a comparison of a vector is a single 1 only when it holds for every element.
When something is wrong

The card is the only place a figure can tell you, so it does:

  • A mistake in the program — an unknown verb or shape, the wrong number of arguments, a bad format string, an unterminated string, a malformed colour or dash word, an expression that does not parse, a block without its end or an end without a block, a repeat inside a repeat, a shape that reads a name it was not given. The whole program is checked and nothing is drawn; the card turns red and shows the first error with its line and column, and how many there are (“3 errors, first on line 7”). The same text appears under the program editor in the settings dialog.
  • A value that cannot be drawn — a coordinate that is not a number or is infinite, a zero radius, a view with no extent. These come and go as a knob turns, so the one statement is skipped, the rest of the figure draws, and the card does not turn red. A quantity left as nan therefore makes its line vanish, but a line that should only sometimes be drawn reads better inside an if.
  • A vector that has no value for the frame — an empty vector on an input. The card turns red, names the line, and draws nothing.

The read-only error property holds the same message, empty when all is well, and is never saved.

Properties
PropertyDescription
program The drawing program. A new node carries a small circle-and-value example so it draws the moment it is dropped.
inputs How many inputs the node has, 1–8 (default 1). Each is a variable under its name.
background-color Fills the card behind the drawing, letterbox bars included (white).
font-family The family every text uses, so one figure is typographically consistent. Empty means the theme default.
stretch Distort the window to fill the card instead of keeping its aspect and centring it; circles become ellipses. Off by default.
play-mode What a film does at its end: once stops and holds the last frame, loop (default) starts again, ping-pong plays back and turns again.
fps Frames per second, 1–60 (default 25). Changing it does not rewind the film.
frames How many frames the film has. 0 (default) takes it from the data; a number makes a film with no vector input at all, and with one it can shorten the film but never lengthen it past the data. At most 10000.
error Read-only: what is wrong with the program, or empty.

In the settings dialog the program has the Figure tab to itself, in a code editor with line numbers and the error text beneath; Appearance holds background-color, font-family and stretch; Animation holds play-mode, fps and frames; the input count and names are on Inputs.
