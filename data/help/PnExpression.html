Calculator

Group: Filters. Type: PnExpression.

Evaluates a small algebraic expression on every incoming message and writes the result to data.value. Before evaluating, the node binds every numeric member of the incoming data bag as a variable, addressable by its member name — so data.value is available as value, a sibling data.temp as temp, and so on. This lets one node combine several readings, e.g. (value * 1.8) + 32 to convert a Celsius reading to Fahrenheit.

PropertyDescription
expression The expression to evaluate. Defaults to value (passes data.value straight through).
Language
  • Numbers: 12, 12.3, .5.
  • Variables: any numeric data-bag member, e.g. value, value1, offset.
  • Operators: + - * / with the usual precedence, parentheses for grouping, and unary minus.
  • Modulo: %, at the same level as * and /. The result takes the sign of the divisor, so -1 % 8 is 7, which is what wrapping an address or a counter wants. Works on fractions too (5.5 % 2 is 1.5).
  • Bitwise: & (and), | (or), ^ (exclusive or — not a power; that is pow(x, y)), << and >> (shifts), and unary ~ (not). Each operand is cut to its whole-number part and treated as a 64-bit signed integer; >> keeps the sign, so -8 >> 1 is -4. A value that is not a finite number, does not fit 64 bits, or a shift count outside 0–63 gives nan instead of an error. Results above 253 lose their lowest bits, because every value is carried as a double. Binding, tightest first: * / %, + -, << >>, &, ^, |, comparisons — so value & 1 == 1 means (value & 1) == 1. Example: the low 4 bits of an instruction word are value & 15 and the opcode above them is value >> 4 (there are no hex literals).
  • Comparisons: < > <= >= == !=. These bind looser than every other operator and evaluate to 1.0 (true) or 0.0 (false), so a comparison result can feed straight into further arithmetic — e.g. (value > 100) * 5.
  • Functions — trigonometry (angles in radians throughout): sin, cos, tan, their inverses asin, acos, atan, the reciprocals cot, sec, csc, and atan2(y, x) — the angle from the positive x axis to the point (x, y), using the signs of both to get the right quadrant, which atan(y/x) cannot. The reciprocals have poles and do not hide them: cot and csc are infinite at every multiple of pi, sec a quarter turn away.
  • Functions — angles: degrees(x) and radians(x). Every trig function above wants radians while every knob, dial and compass bearing is in degrees, so sin(radians(bearing)) is the shape most sheets want — and it is what bearing * pi / 180 was trying to say.
  • Functions — hyperbolic: sinh, cosh, tanh and the inverses asinh, acosh, atanh. cosh is the shape of a hanging cable; tanh is the S-curve that squashes any number into −1…1 without a comparison.
  • Functions — powers, roots and logarithms: sqrt, cbrt — the cube root, and the one root that accepts a negative (cbrt(-8) is -2, while pow(-8, 1/3) is nan); exp, exp2; pow(x, y) — x raised to the power y, and the only way to spell a power here, because ^ is bitwise exclusive-or (2 ^ 10 is 8, while pow(2, 10) is 1024); hypot(x, y) — sqrt(x*x + y*y) without the overflow the written-out form can suffer; and the logarithms log(x), which is the natural one, ln(x), which is the same function spelled so you can be sure, log10, which is what most people mean when they write log, log2, and log(x, base) for a base the sheet computes. expm1(x) and log1p(x) are exp(x) - 1 and log(1 + x) computed without the cancellation that costs the written-out form every significant digit near zero — reach for them for a small interest rate or a decay over a short interval.
  • Functions — rounding, remainder and sign: abs, floor, ceil, round, trunc, sign, fmod(x, y) and copysign(x, y). round sends a half away from zero (round(0.5) is 1, round(-0.5) is -1, round(2.5) is 3) rather than to the nearest even number; trunc cuts toward zero, which is where it differs from floor on a negative (trunc(-1.7) is -1, floor(-1.7) is -2); sign is -1, 0 or 1 — sign(0) is 0, because zero has no direction to report; fmod is the remainder that keeps the sign of x, where the % operator keeps the sign of the divisor (fmod(-7, 3) is -1 and -7 % 3 is 2, and both are wanted); and copysign gives x the sign of y, which is how to say “the same direction as” without a comparison.
  • Functions — testing a value: isnan(x), isinf(x) and isfinite(x), each 1.0 or 0.0. Since an undefined result travels on rather than stopping the sheet (below), these are how a program asks about one — isinf answers for an infinity of either sign, and a program that cares which asks sign as well. They multiply straight into a gate: isfinite(v) * v.
  • Functions — curves with names: sinc(x) is sin(x)/x with the hole at zero filled in (sinc(0) is 1, not nan) — the unnormalised convention, so its first zero is at pi, and it is the envelope of a single slit’s diffraction pattern. erf(x) and erfc(x) are the error function and its complement, the shape of every diffusion, noise and measurement-error curve (they sum to 1). j0(x) and j1(x) are the Bessel functions of the first kind — what a circular aperture needs where a slit needed sinc.
  • Functions — choosing and bounding: min(a, b) and max(a, b), which skip a nan operand rather than passing it on (min(nan, 3) is 3), and clamp(x, lo, hi), which holds x between the two bounds. clamp exists because min(max(x, lo), hi) is what people write instead and get the order wrong in; if the bounds are crossed (hi below lo) the lower one wins, and a nan value stays nan rather than becoming a bound.
  • Functions — choosing, shaping and easing: if(cond, a, b) — a when cond is anything but zero, b when it is zero (see below); lerp(a, b, t) — the straight line between two numbers, a + (b - a) * t, so t = 0 gives a and t = 1 gives b exactly, and a t outside that range carries on along the same line; step(edge, x) — 0 below the edge and 1 at or above it, which is x >= edge under a name; and smoothstep(lo, hi, x) — step’s eased twin, flat at 0 below lo, flat at 1 above hi, and an S-curve between whose slope is zero at both ends. Bounds the same way round are a ramp of no width, so smoothstep becomes step; bounds the other way round run the ramp backwards, which is a handy way to fade something out.
  • Arguments are separated by commas, and a call with the wrong number of them is reported straight away, as a mistake in the expression — saying what the function actually takes, down to “1 or 2 arguments” for one like log that accepts either.
  • Constants: pi and e. They are not variables — an input member actually named pi is used in preference, so nothing you bind can clash with them.

Choosing with if. It picks an arm, it does not weigh them: if(0, sqrt(-1), 1) is 1, where the multiplication trick this replaces — cond * a + (1 - cond) * b — would give nan, because the arm nobody chose still gets multiplied in. Zero is false and any other number is true, so a comparison (1.0/0.0) drops straight in; a nan condition gives nan, since a question with no answer cannot pick an arm either.

One thing to know about if and vectors. A comparison collapses a vector to a single 1.0/0.0 — true only when every element passes — so if(arr > 0, a, b) chooses once for the whole vector, not element by element. A condition built from a function behaves differently, because functions map: step(0, arr), isfinite(arr) and sign(arr) each give a vector of 1s and 0s, and if(isfinite(arr), arr, 0) therefore does choose per element. If you want a per-element decision, build the condition with a function rather than with < or >.

When there is no answer. A result mathematics does not define is a value here, not an error: sqrt(-1), acosh(0) and asin(2) are nan, log(0) and cot(0) are infinite, and each travels on down the wire like any other number — exactly as 1 / 0 always has. No function stops the sheet. That is deliberate: a gap in one sample of a curve should not take the whole plate down with it.

Vectors

If a bound variable is a $pnvector (a large numeric array carried out-of-band; see the message manual), the Calculator treats it as a plain bag of numbers — not a mathematical vector. Every operator just does the scalar thing element by element:

  • A scalar and a vector broadcast: 2 * arr doubles every element and yields a vector.
  • Two vectors combine elementwise: a * b multiplies matching positions. If they differ in length the result is as long as the longer one and each surplus tail element passes through unchanged — [2, 3] * [3, 4, 5] is [6, 12, 5].
  • Functions map over every element: sin(arr) takes the sine of each. A function of two or more arguments follows exactly the operator rules above — atan2(ys, xs) broadcasts and pairs up element by element just as ys * xs would, and clamp(xs, 0, 10) holds every element between the two scalars. Where one argument is a shorter vector than another it runs out, and from there the first argument that still has an element passes through unchanged — so a bound vector shorter than the value it bounds leaves the rest of the value alone rather than clamping it against nothing.
  • A comparison always collapses to a single 1.0/0.0: true only when every element passes (e.g. arr > 0 is 1.0 iff all elements are positive), so it still works as a gate.

A vector result is written to data.value as a new $pnvector; the input vector is never modified in place.

Statements and assignment

The expression may hold several statements, one per line (blank lines are ignored). A statement is either a bare expression or an assignment name = expr, which binds name for use by later lines. All statements are evaluated in order and data.value takes the value of the last one — so a multi-line expression usually ends with a bare expression.

Each assigned name is also written to the outgoing message as a numeric data-bag member, so one Calculator can emit several computed fields. (The reserved value, success and output members are always set from the final result, so assigning them has no lasting effect.) 

expression: (12.3 * value1) + (1 / 2)
expression: sin(value) + 1
expression: (value - 32) * 5 / 9
expression: value >= 100        (1 when at/above the threshold, else 0)

multi-line, binding intermediate names and emitting several fields:
    fahrenheit = value * 1.8 + 32
    kelvin     = value + 273.15
    fahrenheit                    (-> data.value, plus data.fahrenheit, data.kelvin)
Output

On success the node sets data.value to the computed number (or a $pnvector when the result is a vector), data.success to true, and data.output to the formatted result; any names assigned by the expression are added as members too. If the expression cannot be parsed (a syntax error in the property) or evaluated (an unknown variable or function), the message is still forwarded but flagged: data.success is set to false and the reason is placed in data.error and data.output, with data.value left unchanged.
