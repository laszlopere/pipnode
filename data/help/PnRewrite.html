Rewrite

Group: Filters. Type: PnRewrite.

Replaces the incoming message with one assembled from a JSON template authored in the settings dialog. The template editor uses GtkSourceView with JSON syntax highlighting, line numbers and auto-indent, so editing a multi-line envelope feels like editing the same JSON in a text editor.

Every ${path/to/field} occurrence in the template expands to the value addressed by path against the incoming message. The lookup root carries topic, id, created and data (the payload bag), so for example ${data/value} resolves to the data bag's value member and ${topic} to the incoming topic. A missing path renders as the literal null, so the template stays parseable even when an upstream node has not produced the field yet.

Substitution is context-aware: the expander tracks whether the cursor sits inside a JSON string literal and picks the form that keeps the rendered document parseable.

  • Value slot (after : or , / [) — the placeholder emits a complete JSON token. Strings come out quoted; numbers, booleans and null come out as bare tokens; objects and arrays come out as compact JSON. "orig": ${data/value} with a numeric value of 42 yields "orig": 42.
  • Inside a string literal — the placeholder emits the resolved value with JSON string-escape rules applied but without surrounding quotes, so it splices into the string in place. "topic": "rewritten/${topic}" yields "topic": "rewritten//pnode/…".

After placeholder expansion the rendered text is parsed as JSON:

  • An object carrying a top-level topic or data member is treated as an envelope: the topic string overrides the outgoing topic and the data object replaces the outgoing data bag.
  • Any other object is treated as the new data bag in its entirety.

The message id and created timestamp are preserved either way, so a debug pane downstream can still correlate the rewritten message with its origin.

PropertyDescription
template JSON template the outgoing message is built from. Supports ${path/to/field} placeholders.
{
  "topic": "${topic}",
  "data": {
    "value":  ${data/value},
    "output": "${data/output}",
    "source": "${topic}",
    "id":     "${id}"
  }
}
