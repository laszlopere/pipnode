Value Trend

Group: Filters/Gate. Type: PnValueTrend.

Splits a stream of numbers by which way they are moving. The node remembers the last value it let through and compares every arriving data.value against it: a bigger value leaves, unchanged, by the rising output, a smaller one by falling. An equal value is dropped, and so is the very first message — there is nothing to compare it against, it only sets the starting reference.

OutputGets
risingthe value went up
fallingthe value went down
unchangedonly when unchanged-output is on: the value stayed put, or moved less than min-change

min-change is a deadband for noisy readings: a move smaller than it is not counted as a rise or a fall. The reference stays on the last value that was actually forwarded rather than on the last value seen, so small steps accumulate — with a deadband of 5 a sensor creeping 100, 102, 104, 106 stays quiet until 106, which is 6 above the reference of 100. A move of exactly the deadband width does trip. With the default min-change of 0 every change at all is a rise or a fall.

Messages whose data.value is missing or holds text are dropped and leave the reference alone, so a stray message cannot break a running trend. Booleans count as 1 (true) and 0 (false).

Use Threshold when what matters is being above or below one level rather than the direction of travel, Edge to react to a boolean success flipping, and Value Router to sort messages into numeric bands.

PropertyDescription
min-change Deadband width. Moves smaller than this count as unchanged. Default 0, which splits on any change.
unchanged-output Adds a third output carrying the messages that neither rose nor fell, instead of dropping them. Off by default. The first message is dropped either way.
