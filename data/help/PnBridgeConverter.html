Bridge Converter

Group: Network. Type: PnBridgeConverter (subclass of PnHttp).

Cross-chain swap converter. Send it a number in from units and it asks a real bridge what it would actually pay out, then emits that in to units. It is the dealable counterpart of the FX Converter: where that one multiplies by a mid-market reference price, this one reports what a provider would really deliver — spread, flat network fee and per-pair limits already taken out.

Its sibling Bridge Quote asks the same providers the same question on a timer, for a fixed reference amount. Reach for this node instead when the amount is not fixed — it comes off a Knob, a wallet balance, a calculation upstream.

One message in, one message out — a round-trip apart

There is no periodic fetch. Bridge pricing is amount-sensitive: a flat network fee dominates a small swap, so a cached rate cannot honestly be re-scaled to a new amount. The node has to ask again for every amount, and it only has an amount once a message arrives.

That has one consequence worth knowing before wiring it up: the answer is emitted when the provider replies, not from the input handler. The message that arrives is the message that leaves — fields an upstream node set are still on it — but it leaves a network round-trip later. Nothing is passed through in the meantime, because an unconverted amount travelling on would look exactly like a conversion that happened to be the identity.

Only one request is in flight at a time. An amount that arrives while the provider is still answering replaces the one waiting rather than queueing behind it, and the dropped one is noted in the node's log: a converter fed faster than the network answers should quote the newest amount, not work through a backlog of stale ones. That also bounds how hard the node can lean on a provider — one request per round-trip, whatever the input does. Even so, this is a node to drive from a Knob, a manual Inject or a slow timer, not from a fast Interval.

Providers
BridgeHow the quote is obtained
PulseLN One request to api.pulseln.com/c/prices returns the whole cross-rate matrix, the fee table and the per-asset limits; there is no per-amount endpoint, so the payout is computed locally the same way the swap page computes it. PulseLN publishes its fee, so data.fee is filled in.
ChangeNOW The provider quotes the amount directly through its v1 exchange-amount endpoint, and its limits come from a second call to exchange-range. No API key is needed. The provider's cut is folded into the estimate rather than published, so data.fee is omitted. Note ChangeNOW caps a pair well below PulseLN — an amount over the cap comes back as a readable status naming the actual limit, not as a bare HTTP error.
Consumed message
FieldDescription
data.value The amount to convert, in from units. A message without a numeric data.value, or with one that is zero or negative, is answered on the spot with data.success = false and a reason — no request is spent on something a provider would only reject.
everything else Carried through untouched, so a wallet address, a label or a timestamp set upstream is still on the message that comes out.
Properties
PropertyDescription
bridge Which provider to ask: PulseLN or ChangeNOW. Changing it re-points url at that provider's endpoint and drops the last result.
from Asset being sold, picked from the same currency list the FX Converter uses, with icons. Neither bridge lists all of them: a pair the selected provider does not trade marks the node as needing configuration rather than failing at request time.
to Asset being bought. Same set as from; setting it equal to from marks the node unconfigured.
amount Read-only. The amount last converted — the data.value of the message that asked. Set when the request goes out, so a failed conversion still says what was asked about.
quote Read-only. The payout for amount: how much to the bridge would deliver, fees included.
rate Read-only. quote ÷ amount — what one unit really fetched after the spread and fees. This is the number to compare between bridges at the same size.
fee Read-only. Provider fee as a fraction (0.014 = 1.4%). Zero means the provider does not publish it separately.
min-amount / max-amount Read-only. The provider's limits, in from units. Zero means unknown or uncapped.
last-update Read-only ISO-8601 timestamp of the last successful conversion (“Never” until the first one). Cleared the instant bridge, from or to changes.
status Read-only outcome of the most recent conversion: OK, Never converted, or Conversion failed: … with the reason. The same detail goes to the per-node log.
url Endpoint base for the selected bridge, so a self-hosted proxy can be substituted. Normally left alone: picking a bridge sets it.

The results are stored with the worksheet, so reopening a flow still shows what last came through. Nothing is re-emitted from them — unlike Bridge Quote, this node speaks only when spoken to.

There is no period row. The node has no schedule, so a poll interval would be a knob that does nothing; the inherited property is pinned and used only as the request timeout.

Emitted message

One message out per message in, on the incoming message's own topic:

FieldDescription
data.value The payout, in to units — the canonical number of the message, replacing the amount that came in.
data.rate Effective rate after fees, at this size.
data.amount The input amount, so the answer still says what it was an answer to.
data.from / data.to Ticker codes, e.g. PLS and BNB.
data.bridge Provider name, so a merged stream stays attributable.
data.success Whether this message produced a real quote.
data.swappable false when the provider would price this swap but not execute it right now — its payout pool for to is closed, or the amount falls outside min-amount…max-amount. data.warning says which. The rate is still reported and data.success stays true: the price is real, only the execution is blocked.
data.deprecated The mirror of data.success, carried for parity with Bridge Quote so one downstream chain can read either node.
data.output Human-readable summary, or the failure reason.
data.fee, data.min_amount, data.max_amount, data.speed_forecast, data.warning Present only when the provider publishes them — a missing field means “not published”, which is not the same as zero.
Priced but not swappable

A route can be perfectly well priced and still be shut, and both providers say so rather than refusing to quote. PulseLN publishes a per-asset pool state and a floating size band (its swap page currently shows “$1 MIN, $1000 MAX”, converted to from units at the live price, so an amount can fall out of range with nothing reconfigured); it still displays the payout and only greys its Swap Now button. The node does the same: it reports the rate, sets data.swappable to false and explains why in data.warning. Wire that into a Filter or Comparator if you want to act only on executable quotes.

Caveat

This is a quote, not a promise. Both bridges re-quote when a swap is actually created, and PulseLN's endpoint is undocumented, so treat the number as a well-informed estimate rather than a commitment.
