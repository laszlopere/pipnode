Graph

Group: Sinks. Type: PnGraph.

Sink that summarises a numeric value plucked from each incoming message. The header is rendered at twice the canonical width; below it (with a small gap) a plot rectangle shows the data over the configured time window. Two presentation modes are available: a sliding line graph of the value over time, or a frequency histogram that bins the in-window samples by value to reveal where they are clustered — useful for distributions like request latencies or per-message byte counts. Plotting is done with PLplot.

Two parallel rings are kept per node, per topic. The time-series view reads from a ring of up to 200 fixed-width time buckets — the active count is the x-buckets setting — that store running totals only (about 8 KB), so it summarises arbitrary arrival rates over arbitrary windows without growing. The distribution view reads from a ring of 2048 raw samples (about 32 KB); in long-window resolutions (1 day, 1 week) at high arrival rates the ring shows the most recent 2048 samples that fell inside the window, not every sample seen. Both rings are fed unconditionally, so switching the view never starts from an empty plot.

Multi-topic 3D mode

Every distinct msg.topic on the input wire is tracked as a separate data series with its own pair of rings. As long as only one topic has been seen (the common case, including feeds that never set a topic at all), the plot is the familiar 2D one. Once a second topic arrives, both views auto-switch to a 3D projection: each series gets its own slot along the Z axis in arrival order — the first-seen topic sits closest to the viewer — with time (time-series view) or value (distribution view) running along X and the value or sample count rising along the vertical Z axis. Series colours are derived from line-color by walking the HLS hue wheel in golden-angle steps so adjacent series read distinctly without the user having to pick a palette. The first series keeps the line-color exactly so single-topic worksheets look unchanged. Up to 12 distinct topics are tracked; messages introducing a 13th topic are dropped silently so a pathological feed that synthesises a new topic per message cannot grow memory without bound.

PropertyDescription
key JSON path (“/”-separated, e.g. data/value) to the value plotted on the Y axis. Resolves against the same root used by Format's placeholders. Numbers are accepted directly; strings are parsed too — either as base-10 (with optional sign and fractional part) or as a hex literal with a 0x/0X prefix, so hex-encoded quantities such as a byte count or a value field can be plotted as-is. Values are coerced to a 64-bit double (≈16 decimal digits exact); precision loss past that point is well below pixel resolution. Missing, unparsable, or non-finite values are silently dropped.
resolution Total time span summarised by the plot: 1 minute, 15 minutes, 1 hour, 1 day, or 1 week. In the time-series view it sets the X-axis time span; in the distribution view it acts as the rolling cutoff that decides which samples are binned (samples older than the window are ignored, so a 1 minute window shows the distribution of the last minute's traffic, 1 hour the last hour's, and so on). Switching mid-stream takes effect on the next paint; existing time-series samples whose bucket maps onto a stale slot under the new window are discarded lazily.
x-buckets How many time buckets the window is split into along the X axis (2–200, default 200). Each bucket aggregates the samples that fall in its slice of the window — their count, mean, and spread — and the time-series view draws one point per bucket (or, with the Error bars draw-style, one box-and-whisker). Fewer, wider buckets fold more samples together for a smoother line and a fuller spread per error bar; more, narrower buckets track finer detail. Like resolution it changes the bucket width, so changing it discards the existing time buckets lazily and the plot rebuilds over the next window. Has no effect on the distribution view, which bins by value rather than by time.
data-view What the plot represents. Time series (default) plots each value against time, most recent sample on the right (X axis is time). Distribution bins the in-window samples by value into 40 fixed-width bins and plots how often each value occurs (X axis is value, Y axis is the count) — the resulting shape reads as a discrete picture of where the values cluster. Bin edges auto-range over the live [min, max] of the in-window data. In multi-topic 3D mode every series is binned against the same shared [vmin, vmax] so bars at the same value line up across ribbons.
draw-style How the chosen data-view is drawn (the “Draw as” setting): Points marks each data point with a filled circle, Lines (default) connects them with a polyline, Bars draws each as a filled bar from the baseline, and Error bars draws each time bucket as a box-and-whisker. The two settings are independent, so e.g. a time series can be shown as points (a scatter) or bars (a column chart), and a distribution as a line (a frequency polygon) instead of bars (the classic histogram). Honoured for single-topic plots; multi-topic 3D plots fall back to the polyline form for the time-series view and to bars for the distribution view.

The Error bars style is built for the time-series view: it draws on the same time buckets that back the line, showing how much each bucket’s samples spread rather than just their mean. Per bucket the whisker spans the minimum…maximum sample, the box spans the mean ± 1 standard deviation, and a tick marks the mean. Each box is filled green when its mean rose versus the previous (older) bucket and red when it fell, so the trend reads at a glance; the first bucket and any flat step are drawn neutral grey. In the distribution view (where there is no per-bucket spread) the style falls back to bars.

line-color Colour of the plotted data — the polyline, the point markers, or the bar fill, depending on draw-style. Defaults to a dark blue that reads well against a white background. In multi-topic 3D mode it is the colour of the first (front-most) series; subsequent series walk the hue wheel in golden-angle steps from this base.
line-width Stroke width of the data polyline, in pixels (1–8, default 2). Also scales the marker size of the Points draw-style.
axis-color Colour of the plot frame, ticks, and tick labels. The same colour is used for the thin frame painted around the plot rectangle.
background-color Fill colour of the plot rectangle behind the polyline. Defaults to white.
show-grid When enabled, draws a thin grid through every major tick on both axes for easier reading of values.
log-y Plots the Y axis on a base-10 logarithmic scale, with tick labels printed as decade powers (10⁰, 10¹, 10², …). Currently honoured only in the distribution view, where it is useful for long-tailed distributions — e.g. network byte counts that cluster around a few hundred bytes but pick up an occasional billion-byte outlier — whose tallest bars would otherwise crush the smaller ones flat. Single-occurrence bins still draw with a visible height because the log floor is set to log10(0.5) rather than −∞.
y-from-zero Anchors the Y axis at zero instead of auto-fitting it tightly around the data. By default the axis hugs the live [min, max] with a little headroom, so a series of large values that wobbles only slightly fills the whole height and exaggerates tiny changes; enabling this pins the baseline to 0 so movement stays in proportion to the absolute value. A series that already straddles zero is unaffected (zero is in range either way). Honoured in the time-series view on a linear axis — it has no effect on a logarithmic Y axis, which cannot reach zero.

In the node's settings dialog these properties are split across two tabs: Appearance collects how the plot is drawn (draw-style, line-color, line-width, axis-color, background-color, show-grid), while Data collects what is plotted and how the value axis is framed (key, resolution, x-buckets, data-view, log-y, y-from-zero).
