CPU Temperature

Group: Host monitoring. Type: PnTemp.

Auto-triggered probe that samples a host's CPU temperature sensors every period seconds and emits a single aggregated value (in degrees Celsius) as data.value. Sources are collected from /sys/class/hwmon/hwmon*/ entries whose name matches a known CPU driver (coretemp, k10temp, k8temp, zenpower, cpu_thermal) and every tempN_input file inside those directories contributes one reading; if no hwmon source is present the node falls back to /sys/class/thermal/thermal_zone*/ entries whose type looks like a CPU thermal zone (x86_pkg_temp, cpu-thermal, coretemp, ...). The aggregation property picks whether data.value is the arithmetic mean or the maximum of those readings.

When hostname is empty or "localhost" the sensor files are read off the local filesystem directly; any other value is treated as a remote host and the sample is fetched over passwordless SSH (ssh -o BatchMode=yes … hostname sh -c <snippet>) on a worker thread, so an unreachable target cannot freeze the GUI.

The emitted message carries data.value (aggregated temperature in °C), data.average, data.min, data.max, data.count (number of sensors that contributed), data.unit (always "°C"), data.hot (label of the hottest sensor — useful when running with aggregation = "average" and you still want to know which core is the outlier), data.aggregation (the active mode, as the string "average" or "maximum"), data.readings (a JSON array of {label, value} objects, one per sensor, for downstream nodes that want the raw breakdown), data.host (normalised to "localhost" for the local path), data.success, and data.output (a one-line summary — either the aggregated reading with sensor count, or the failure reason). When the SSH probe fails the remote stderr or the spawn error message is folded into data.output so a downstream Debug Print shows the user what went wrong.

A successful sample with zero matching sensors is treated as a failure (data.success = false, data.output = "no CPU temperature sensors found") rather than silently emitting 0.0 — the diagnostic is more useful than a misleading number on the wire. This typically means the host either uses an unusual sensor driver not in the matched list, or the kernel was built without the appropriate hwmon module.

The remote login defaults to your ambient SSH setup: the local desktop account and whatever key your ssh-agent or ~/.ssh already provides, trusting the host key on first sight. To reach the host as a different account, on a non-standard port, with a specific identity file, or under a stricter host-key policy, attach an SSH Login credential from the node's SSH Login picker (the auth-profile property). The credential says how to log in; the hostname field still says where. With none selected the node keeps the original passwordless-SSH behaviour.

PropertyDescription
hostname Host whose CPU temperature to read. Defaults to "localhost"; an empty string is treated the same. Any other value is used as the SSH target — passwordless authentication must already be set up (BatchMode=yes is forced so the probe never prompts for a password).
aggregation How the per-sensor readings collected from the host are collapsed into the single number on data.value: "average" reports the arithmetic mean across every CPU package and every core (good for a whole-system feel), "maximum" reports the hottest single reading (better for spotting a runaway core or a stuck fan). In either mode the unaggregated data.average, data.min, data.max and data.readings members are always populated, so a downstream filter can consult the other view without reconfiguring this node.
period Seconds between samples. The default is 5 s — CPU temperatures only move on the order of seconds (thermal mass of the silicon plus heatsink), so polling faster mostly buys repeated identical readings.
auth-profile Optional SSH Login credential supplying the remote account, port, identity file and host-key policy. Empty (the default) follows the primary SSH Login profile, or — when none is configured — the node's ambient-key behaviour. Stored in the host vault, never in the worksheet file. Separate from hostname, which still selects where to connect.
