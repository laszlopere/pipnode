Disk I/O

Group: Host monitoring. Type: PnDiskIo.

Auto-triggered probe that samples /proc/diskstats every period seconds and emits the live disk-I/O throughput as data.value in the byte multiple chosen by the unit property — one of B/sec, KByte/sec, MByte/sec, or GByte/sec (decimal, 1 KByte = 1000 bytes, matching the convention disk vendors and tools like iostat/dd use). The default is GByte/sec. The figure is computed as the per-second delta of the kernel's cumulative 512-byte sector counters between two consecutive ticks, so the first sample after construction (or after a hostname / device change) carries value = 0 and a "warming up" note in data.output: a real reading needs two samples.

The sample comes from /proc/diskstats directly when hostname is empty or "localhost"; any other value is treated as a remote host and the file is fetched over passwordless SSH (ssh -o BatchMode=yes … hostname cat /proc/diskstats) on a worker thread, so an unreachable target cannot freeze the GUI.

device picks which row to measure. An empty string (the default) sums across every whole-disk row in the file: partition rows (sda1, nvme0n1p1, mmcblk0p1, …) and pseudo-devices (loop*, ram*, zram*, sr*, fd*) are skipped so a parent disk is not double-counted through its partitions. A concrete value ("sda", "nvme0n1", "dm-0", …) restricts the reading to that row.

The emitted message carries data.value (read + write throughput in the configured unit), data.read, data.write (the two halves of the sum, same unit), data.unit (the short string matching the chosen unit property — "B/sec", "KByte/sec", "MByte/sec" or "GByte/sec"), data.device (the device(s) that contributed: a single name, an empty string when no whole-disk row was found, or a "+"-joined list when the all-disks path summed several), data.host, data.success, and data.output (a one-line summary — either the GByte/sec figure broken into its read/write halves or the failure reason). When the SSH probe fails the remote stderr or the spawn error message is folded into data.output so a downstream Debug Print shows the user what went wrong; when the file was read but no row matched the configured device, data.output explains that explicitly.

The remote login defaults to your ambient SSH setup: the local desktop account and whatever key your ssh-agent or ~/.ssh already provides, trusting the host key on first sight. To reach the host as a different account, on a non-standard port, with a specific identity file, or under a stricter host-key policy, attach an SSH Login credential from the node's SSH Login picker (the auth-profile property). The credential says how to log in; the hostname field still says where. With none selected the node keeps the original passwordless-SSH behaviour.

PropertyDescription
hostname Host whose /proc/diskstats to read. Defaults to "localhost"; an empty string is treated the same. Any other value is used as the SSH target — passwordless authentication must already be set up (BatchMode=yes is forced so the probe never prompts for a password). Changing this property mid-flight discards the previous sample so the next emitted value is the "warming up" zero rather than a spurious cross-host delta.
device Block-device name to measure ("sda", "nvme0n1", "mmcblk0", "dm-0", …). An empty string (the default) sums across every whole-disk row of /proc/diskstats. Partition rows and the loop/ram/zram/sr/fd pseudo-devices are skipped on the all-disks path so a parent disk is not counted twice. Changing this property mid-flight discards the previous sample (same reason as for hostname).
unit Output unit for data.value: B/sec, KByte/sec, MByte/sec, or GByte/sec (decimal multiples, 1 KByte = 1000 bytes). The default is GByte/sec. The chosen short string is also emitted on data.unit so a downstream Graph axis label can pick it up verbatim. Changing this property does not invalidate the previous sample — the bytes/sec computation is the same, only the divisor differs, so the next emitted reading is a real number rather than another "warming up" zero.
period Seconds between samples. The default of 2 s keeps the per-tick delta well above the noise floor the kernel's sector-counter rounding introduces while still feeling responsive in a downstream Graph.
auth-profile Optional SSH Login credential supplying the remote account, port, identity file and host-key policy. Empty (the default) follows the primary SSH Login profile, or — when none is configured — the node's ambient-key behaviour. Stored in the host vault, never in the worksheet file. Separate from hostname, which still selects where to connect.
