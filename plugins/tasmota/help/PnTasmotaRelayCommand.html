Tasmota Relay Command

Group: Tasmota. Type: PnTasmotaRelayCommand.

Inverse of Tasmota Relay Status. Reads data.value off each inbound message, turns it into the Tasmota relay-control message a downstream MQTT Sink can publish, and forwards. Closes the loop on a flow like Switch → Tasmota Relay Command → MQTT Sink without intervening Format or Rewrite nodes — the Tasmota-specific topic + payload shape is baked in.

Conversion
Inbound data.valueOutbound
> 0.5 (e.g. 1.0) data.payload = "ON", data.value = 1.0
≤ 0.5 (e.g. 0.0) data.payload = "OFF", data.value = 0.0

The envelope topic is rewritten to cmnd/<switch-name>/POWER so the downstream MQTT Sink — which takes the publish topic from the envelope — publishes straight to the right Tasmota command endpoint. Messages without a usable numeric data.value leave the relay alone (same rule the read-side Tasmota Relay Status uses), so the pair stays internally consistent.

Configuration
PropertyDescription
switch-name Tasmota device name to command. Stamped into the outgoing envelope topic as cmnd/<switch-name>/POWER and copied to data.device. Mandatory by design — there is no default, since silently defaulting would risk flipping the wrong physical relay. An empty field puts the node in the red “configuration required” state and rejects every message until the user fills it in.
Output shape

The inbound envelope is rewritten and the data bag overwritten in place; downstream sees:

MemberValue
envelope topic cmnd/<switch-name>/POWER
data.payload String "ON" or "OFF" — exactly what Tasmota's command parser expects, and the shape MQTT Sink's default payload path publishes as raw bytes without quoting.
data.value Normalised 1.0 / 0.0 mirror of the on/off decision, so a parallel branch (an LED indicator wired off the same point) can shadow the state without parsing the payload string.
data.success true on every forwarded message.
data.device The configured switch-name, suitable for downstream per-device routing or logging.
data.output Human-readable summary, e.g. sonoff19: command power on.
Wiring example
Switch (slide)
    → Tasmota Relay Command (switch-name = sonoff19)
        → MQTT Sink (url = tcp://mqtt.homelab.local:1883,
                          retain = false)

Click the slider on Switch; the value flips between 1.0 and 0.0; Tasmota Relay Command turns that into cmnd/sonoff19/POWER + "ON"/"OFF"; MQTT Sink publishes, and the physical relay clicks. Closing the loop with a parallel MQTT Source → Tasmota Relay Status → Switch branch gives the canvas switch a way to follow state changes commanded from elsewhere (the Tasmota app, the wall button, another flow).
