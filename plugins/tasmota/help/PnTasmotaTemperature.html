Tasmota Temperature

Group: Tasmota. Type: PnTasmotaTemperature.

Filter / transformer node that watches an upstream MQTT stream for Tasmota SENSOR publishes, picks the temperature reading out of the per-sensor JSON wrapper, and re-emits the message with the reading promoted to the standard data.value / data.unit / data.device shape every other node in the palette already speaks.

What gets through

Wire a MQTT Source (or any other producer that emits data.payload as a JSON object) into the input port. The node looks for a numeric Temperature member in the payload — first at the top level, then in each direct child object (Tasmota wraps the reading in a per-sensor object such as AM2301, DHT22 or BMP280). Messages whose payload does not contain a Temperature member are dropped silently.

Output shape

The emitted message preserves the input's envelope topic and id and mutates only the data bag:

  • data.value — the temperature reading as a JSON number (no rounding, the producer's precision is preserved).
  • data.unit — "C", "F" or whatever the publish carried in TempUnit. Defaults to "C" when the firmware omits the field — that matches the Tasmota build default.
  • data.device — the device id parsed from the MQTT topic (the second-to-last segment, e.g. "tasmota13" from "tele/tasmota13/SENSOR"). Omitted when the topic has fewer than three segments.
  • data.output — one-line summary suitable for a Debug pane: "tasmota13: temperature 22.8 °C".
  • data.success — true.
Wiring example
MQTT Source (topic = tele/+/SENSOR)
    → Tasmota Temperature
        → Graph     (auto-plots data.value over time)
        → Debug View (sees the one-liner output)

The same shape works downstream of any producer that emits Tasmota- style JSON publishes — an HTTPS Tunnel Receiver that the firmware posts to, a synthetic Injector for testing, etc.
