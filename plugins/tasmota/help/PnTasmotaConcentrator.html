Tasmota Concentrator

Group: Tasmota. Type: PnTasmotaConcentrator.

The collector half of the Tasmota concentrator, companion to the Tasmota Probe. Sits on a branch from an MQTT Source and gathers the per-device replies the devices publish on stat/<device>/STATUS# (and, optionally, the tele/<device>/STATE and tele/<device>/SENSOR telemetry). It accumulates one record per device and emits a single combined snapshot of the whole fleet to a downstream Debug, table, or HTTP view.

How the two nodes cooperate

The Probe is the active half: it discovers devices from the telemetry stream and fires a Status query at each one. The Concentrator is the passive half: it consumes the STATUS# replies those queries provoke. They are kept as separate nodes so each can be wired independently — the Probe's output to an MQTT Sink, the Concentrator on a parallel branch to a view — and composed into the full discover → poll → collect → present loop.

Why the replies arrive in fragments

A Tasmota Status 0 query does not answer with one message: the firmware splits its report across a dozen separate publishes — STATUS, STATUS1 … STATUS11 — each on its own topic and each carrying a distinctly-keyed JSON object (Status, StatusNET, StatusSTS, …). This node stitches those fragments back into one object per device.

How it merges

Each accepted payload is shallow-merged at the top level into the device's record: every member of the incoming object is copied in, replacing any member of the same name. Because Tasmota keys each section distinctly, the sections accumulate side by side rather than clobbering each other; re-sending a section simply refreshes it. The device is identified by the <device> segment of the topic (the canonical Tasmota <prefix>/<device>/<command> topology). The group topic tasmotas is never collected.

When it emits

Whenever an accepted message arrives and at least interval seconds have elapsed since the previous emit, the node sends one combined message whose data.devices member maps every known device to its merged record. The min-interval debounces the burst of STATUS# replies that a single Status 0 provokes into one downstream update.

Configuration
PropertyDescription
interval Minimum seconds between two emitted snapshots. Default: 2. Set to 0 to emit a snapshot on every collected message.
timeout Drop a device from the snapshot when its most recent reply is older than this many seconds, so the snapshot reflects only devices still reporting. Default: 0 (keep every device once seen).
merge-telemetry When on (the default), also fold tele/<device>/STATE and tele/<device>/SENSOR telemetry into each record. Turn off to collect only the explicit STATUS# sections.
Output shape
MemberValue
envelope topic tasmota/devices
data.devices Object mapping each known device name to its merged record, e.g. { "sonoff19": { "Status": …, "StatusNET": … }, "sonoff47": { … } }.
data.value The number of devices in the snapshot.
data.success true on every emitted snapshot.
data.output Human-readable summary, e.g. 2 devices: sonoff19, sonoff47.
Wiring example
MQTT Source (topic = tele/#, stat/#)
    → Tasmota Probe (request  = Everything (Status 0),
                          interval = 300)
        → MQTT Sink (url = tcp://mqtt.homelab.local:1883)

MQTT Source (topic = stat/+/STATUS#, tele/+/STATE, tele/+/SENSOR)
    → Tasmota Concentrator (interval = 2)
        → Debug

The Probe publishes cmnd/<device>/Status 0 per discovered device; each device answers with its STATUS# fragments, which the parallel branch's Tasmota Concentrator merges per device and presents as one combined snapshot in Debug.
