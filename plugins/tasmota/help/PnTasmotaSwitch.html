Tasmota Switch

Group: Tasmota. Type: PnTasmotaSwitch.

Bidirectional device node for a single Tasmota relay. Merges the on-canvas slide switch (Switch), the read-side POWER status decoder (Tasmota Relay Status) and the write-side POWER command encoder (Tasmota Relay Command) into one node so the canonical “show the relay state, let the user flip it” worksheet collapses from a five-node chain to three: 

MQTT Source → Tasmota Switch (switch-name = sonoff19) → MQTT Sink

The factored trio (Switch + Tasmota Relay Status + Tasmota Relay Command) is still available for users who want the explicit pipeline shape — this node is the device-flavoured shorthand for the common case.

Direction split
DirectionBehaviour
Inbound (MQTT → latch) A message whose envelope topic matches <prefix>/stat/<switch-name>/POWER (or any POWER1..POWER8 multi-relay variant) and whose data.payload is the string ON or OFF syncs the latch silently — the slider position updates but nothing is emitted downstream. The inbound is an authoritative status observation, not a transit message that should fan out; forwarding it would either leak raw MQTT bytes into observer nodes or close a loop back through the sink.
User click (latch → MQTT) Clicking the slider flips the latch and emits a fresh Tasmota command message: envelope topic cmnd/<switch-name>/POWER, with the standard data.payload / data.value / data.success / data.device / data.output shape so a downstream MQTT Sink publishes the literal Tasmota expects, and a parallel observer (LED, Debug, Graph) sees the same value form it would have from the factored chain.

Startup command is opt-in. The base Switch announces its latch state once when a worksheet loads, so downstream nodes learn its position without a click. Because the Tasmota Switch's output is a physical relay command, this is off by default: the relay's true state instead arrives over the inbound stat/…/POWER path, which syncs the slider silently, so opening a worksheet never actuates hardware. Set enforce-on-startup if you want the worksheet to be the source of truth and force the relay to the saved position on load.

Configuration
PropertyDescription
switch-name Tasmota device name (e.g. sonoff19) the node binds to. Inbound: matched against the second-to-last segment of each incoming topic. Outbound: stamped into cmnd/<switch-name>/POWER. Mandatory by design — an empty value puts the node in the red “configuration required” state, rejects every inbound message, and refuses to emit on user-click, since silently defaulting would risk reading or flipping the wrong physical relay.
on Inherited from Switch. Current latch position (persisted in the worksheet so the slider parks back the way the user left it on reload).
enforce-on-startup When enabled, the node emits a cmnd/<switch-name>/POWER command for the saved latch position once shortly after the worksheet loads, forcing the physical relay to match the worksheet on startup. Off by default — opening a worksheet never actuates the relay; the latch tracks the device's reported state instead. Enable it when the worksheet (not the device) is the source of truth for the desired state.
Wiring example
MQTT Source (url = tcp://mqtt.homelab.local:1883, topic = #)
    → Tasmota Switch (switch-name = sonoff19)
        → MQTT Sink (url = tcp://mqtt.homelab.local:1883)

Click the slider on the canvas; the node emits cmnd/sonoff19/POWER with payload ON or OFF; MQTT Sink publishes; the physical relay clicks; the broker echoes stat/sonoff19/POWER back; the MQTT Source forwards it; Tasmota Switch's inbound path sees its own state confirmed and silently moves on (no echo storm). Flipping the relay externally (Tasmota app, wall button, another flow) follows the same return path and the slider tracks the new state.

Observing external changes. Because the inbound path syncs the latch silently, a node wired downstream of the output only sees user-driven changes. If you want an LED to flash on external state changes too, wire it through a parallel Tasmota Relay Status filter off the same MQTT Source: 

MQTT Source
    → Tasmota Switch (switch-name = sonoff19) → MQTT Sink
    → Tasmota Relay Status (switch-name = sonoff19) → LED
Relationship to the factored nodes

This node is a subclass of Switch, so the worksheet's slider-click routing, hit-testing and painting all come from the same implementation — the latch behaviour is shared, only the encode / decode shape is Tasmota-specific. See Tasmota Relay Status and Tasmota Relay Command for the standalone read / write filters that this node bundles inline.
