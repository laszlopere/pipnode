Tasmota Status Request

Group: Tasmota. Type: PnTasmotaStatusRequest.

Read-side companion to Tasmota Relay Command. Treats every inbound message as a bare trigger — the value it carries is ignored — and emits the Tasmota Status query a downstream MQTT Sink can publish to make a device report its configuration and runtime info. Drop it into a flow like Inject → Tasmota Status Request → MQTT Sink without intervening Format or Rewrite nodes — the Tasmota-specific topic + payload shape is baked in.

The device's reply does not come back through this node; it is published by the device on stat/<device>/STATUS (and STATUS1 … STATUS11). Subscribe an MQTT Source to stat/<device>/# to receive it.

What gets sent

The envelope topic is rewritten to cmnd/<device>/Status and data.payload is set to the numeric section selected by the request property, so the device sees exactly Status <n>.

requestSendsAsks for
Everything (Status 0)0 The full report (all sections below at once).
Device parameters (Status 1)1 Power-on state, save flags, boot count.
Firmware version (Status 2)2 Version, build, core / SDK.
Logging & telemetry (Status 3)3 Log levels, telemetry period.
Memory & flash (Status 4)4 Heap, flash layout.
Network (Status 5)5 IP, gateway, mask, MAC, hostname.
MQTT (Status 6)6 Broker host, port, client, topic, full-topic.
Time & location (Status 7)7 Time, timezone, sunrise / sunset.
Connected sensors (Status 8)8 Sensor readings.
Power thresholds (Status 9)9 Power-monitoring limits.
Sensor data (Status 10)10 Sensor data (same shape as tele/…/SENSOR).
Device state (Status 11)11 Device state (same shape as tele/…/STATE).

A Status query is strictly read-only: it never changes the device's configuration, it only asks the device to report it.

Group topic returns no reply. Sending to the tasmotas group topic makes every device act on the request, but Tasmota deliberately suppresses the MQTT response for group (and fallback) topic commands — so a group query yields zero stat/…/STATUS replies. (MQTT wildcards # / + don't help either: they are illegal in a publish topic; * is just a literal.) To actually read information back from a device you must address it individually; to collect from every device, query each one in turn. The auto-discovering, collect-and-present version of that loop is the planned Tasmota concentrator (project TODO item 22).

Configuration
PropertyDescription
device Tasmota device to query. Stamped into the outgoing envelope topic as cmnd/<device>/Status and copied to data.device. Set it to a specific device name (e.g. sonoff_rf_bridge_01) to query just that one — this is the form that returns a reply. Defaults to tasmotas — Tasmota's built-in group topic — which reaches every device at once (an empty field is treated the same way), but see the warning below: a group request is acted on without any reply. Because the query is read-only there is no unsafe default to guard against, so unlike Tasmota Relay Command there is no “configuration required” state.
request Which Status section to ask for — Everything (Status 0) for the full report, or one specific section (see the table above). Default: Everything (Status 0).
Output shape

The inbound message is reshaped and re-topiced in place; downstream sees:

MemberValue
envelope topic cmnd/<device>/Status
data.payload String "0" … "11" — the selected section, the shape MQTT Sink's default payload path publishes as raw bytes without quoting.
data.success true on every forwarded message.
data.device The resolved target (the configured name, or tasmotas).
data.output Human-readable summary, e.g. sonoff_rf_bridge_01: request Status 0.
Wiring example
Inject (button)
    → Tasmota Status Request (device  = sonoff_rf_bridge_01,
                                   request = Everything (Status 0))
        → MQTT Sink (url = tcp://mqtt.homelab.local:1883)

MQTT Source (topic = stat/sonoff_rf_bridge_01/#)
    → Debug

Fire the Inject button; Tasmota Status Request turns the trigger into cmnd/sonoff_rf_bridge_01/Status + "0"; MQTT Sink publishes it; the device answers on stat/sonoff_rf_bridge_01/STATUS…, which the parallel MQTT Source → Debug branch shows. Setting device to tasmotas publishes the request to every device at once, but (per the warning above) none of them reply — for a reply you must name a specific device.
