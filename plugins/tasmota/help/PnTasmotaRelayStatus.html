Tasmota Relay Status

Group: Tasmota. Type: PnTasmotaRelayStatus.

Converts a Tasmota relay-state publish (stat/<device>/POWER carrying the bare strings ON / OFF) into the standard data.value / data.success / data.device / data.output shape the rest of the palette already speaks. Place it downstream of an MQTT Source subscribed to stat/+/POWER (or stat/#) and feed the output into anything that reacts to a numeric on/off — the host's Switch, an LED, a Graph in histogram mode, or an Edge filter that fires on transitions.

Configuration
PropertyDescription
switch-name Tasmota device name the filter listens for. Matched against the second-to-last segment of each incoming topic, so sonoff19 accepts publishes on stat/sonoff19/POWER (and any POWER<N> variant) and silently drops everything else. Leaving the field empty puts the node in the red “configuration required” state and rejects every message — the same convention Injector uses for its empty-text state.
What gets through

A message is forwarded when all three of:

  • The second-to-last segment of its topic equals the configured switch-name exactly. Comparing extracted device names (rather than substring-matching the raw topic) means sonoff1 does not accidentally accept publishes from sonoff19.
  • The last segment starts with the literal text POWER — that covers both the single-relay default and the POWER1..POWER8 multi-relay variants without listing each numbered code.
  • Its data.payload is the string ON or OFF (case-insensitive). Other Tasmota responses that share the POWER topic family (TOGGLE, Blink, PulseTime) are dropped so a downstream edge filter does not see them as a false off-transition.
Output shape

The original envelope (topic, id, source) survives the conversion; the data bag is rewritten so a downstream node sees the canonical numeric form:

MemberValue
value 1.0 when the payload was ON, 0.0 when it was OFF.
success true on every forwarded message — the conversion succeeded, regardless of which state the relay was in.
device The second-to-last topic segment (sonoff19 in stat/sonoff19/POWER), suitable for keying per-device state downstream.
output Human-readable summary, e.g. sonoff19: power on — handy for a Debug sink or a Notify popup.
Wiring example
MQTT Source (topic = stat/+/POWER)
    → Tasmota Relay Status (switch-name = sonoff19)
        → LED                        (visual indicator)
        → Edge → Notify         (popup on every on/off transition)
        → Graph (histogram)          (relay-state timeline)

For multiple devices, drop one Tasmota Relay Status per device and fan the same MQTT source into each — the per-node switch-name field handles the demultiplexing without needing a separate Filter rule.
