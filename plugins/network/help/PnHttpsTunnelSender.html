HTTPS Tunnel Sender

Group: Network. Type: PnHttpsTunnelSender.

Sink-only node that POSTs every PnMessage arriving on its input port to a configured HTTPS URL as a JSON envelope. Designed as the sender side of a pipnode-to-pipnode link: wire any source into this node, point it at a peer pipnode running an HTTPS Tunnel Receiver, and every message the source emits lands on the peer's HTTPS Tunnel Receiver output port.

Wire format

The body posted to the target is the same envelope the HTTPS Tunnel Receiver expects: 

{
  "topic"   : "...",
  "id"      : "...",
  "created" : "...",
  "data"    : { ... }
}

The topic, id and created fields are taken straight from the inbound PnMessage envelope; data is the message's data bag verbatim. Optional fields are omitted when the inbound message does not carry them. The receiver rebuilds the same shape on the other side, so a chain of Source → HTTPS Tunnel Sender → (network) → HTTPS Tunnel Receiver → Sink is structurally indistinguishable from the same source wired straight into the same sink locally.

Authentication

Optional HTTP Basic auth: when both username and password are non-empty the node sends an Authorization: Basic ... header on every request (preemptive auth, no 401-then-retry round-trip), matching what the HTTPS Tunnel Receiver's basic auth domain expects. Either field empty disables auth.

TLS

When verify-tls is FALSE (the default) the node accepts any peer certificate, including the self-signed one the HTTPS Tunnel Receiver mints out of the box — so dropping a Client and a Server onto two worksheets and wiring them together works without any external PKI. Flip verify-tls to TRUE when targeting a real cert (e.g. a Let's Encrypt certificate on the peer); the connection then validates against the system trust store and refuses on any error.

Failure handling

The POST is fire-and-forget: there is no output port, the response body is drained and discarded, and a transport failure or non-2xx status is logged through g_warning rather than propagated downstream. While the URL is unset the node is marked red with a warning glyph and silently drops every incoming message.

PropertyDescription
url Target URL. Defaults to https://127.0.0.1:8443/ so the node pairs with an HTTPS Tunnel Receiver running on its default port on the same machine out of the box; override with the peer's address (e.g. https://peer.example:8443/) once the topology grows past loopback.
username HTTP Basic auth username; empty disables auth.
password HTTP Basic auth password; empty disables auth.
verify-tls Validate the peer's certificate? Defaults to FALSE for the self-signed-server pairing.
