HTTP Basic Auth credentials

An HTTP Basic Auth profile holds the username and password the HTTP Request node and friends present when a server returns an HTTP 401 challenge with WWW-Authenticate: Basic. RFC 7617 Basic authentication encodes the credentials as base64(username:password) and sends them in the Authorization header on every request — effectively plain text on the wire, so this profile is only safe over HTTPS.

What you need from the server

The administrator of the service you are connecting to gives you two strings:

  • a username — an account on the remote service, or an API-key identifier;
  • a password or shared secret tied to that username.

Some common sources:

  • Self-hosted web apps (Grafana, a local Home Assistant install, a router admin page): use the account you created there. Many of these expose Basic auth on a /api/… path even when the UI uses session cookies.
  • nginx / Apache reverse proxies that protect a back-end with an auth_basic realm: the username and password are the ones in the proxy's .htpasswd file. Add a new entry with htpasswd -B /etc/nginx/.htpasswd username (the -B picks bcrypt; reload nginx afterwards).
  • Third-party APIs that use Basic auth as a lightweight "API key + secret" scheme (Twilio, Mailgun, …): the dashboard exposes the pair to copy.
Filling in the profile
FieldWhat goes in it
Username The account name or API-key identifier the server expects in the left-hand side of the Authorization: Basic header.
Password The password (or API secret) for Username. Stored in the host vault (mode 0600 in your config directory); never written into a worksheet file.

The profile is then picked from the Authentication dropdown on the HTTP Request node's settings dialog.

Security note

Basic auth sends the credentials in clear text on every request, so only use it over HTTPS. When the endpoint is http://… on a public network, prefer OAuth, a bearer token, or mutual TLS instead.
