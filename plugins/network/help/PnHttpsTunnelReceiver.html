HTTPS Tunnel Receiver

Group: Network. Type: PnHttpsTunnelReceiver.

Source-only node that listens on a TCP port and emits one PnMessage for every JSON document POSTed to it. Designed as the receiver side of a pipnode-to-pipnode link: a peer pipnode (or any HTTPS client — curl, a script, another service) sends a JSON envelope to https://<host>:<port>/, the node parses it, rebuilds the message, and forwards it on its output port to whatever is wired downstream.

TLS

The node always serves HTTPS. Out of the box, with no configuration, it generates a self-signed RSA 2048 certificate (CN=pipnode, ~10 year validity) and stores it under $XDG_DATA_HOME/pipnode/ (typically ~/.local/share/pipnode/default-cert.pem and default-key.pem, with the key file chmod 0600) on first start. Subsequent starts pick the same files back up so the server's identity is stable across restarts — dropping the node onto a worksheet and wiring it up is enough; no external setup needed. Clients connecting to a self-signed endpoint must pin the certificate or skip verification (curl -k, etc.).

When you want a real certificate (a Let's Encrypt cert, a private PKI cert, ...), point cert-path and key-path at the PEM files instead of the auto-generated defaults; the supplied pair is used as-is and the auto-generation step is skipped. Clearing both fields falls back to an ephemeral, in-memory self-signed cert that does not survive a restart.

Authentication

Optional HTTP Basic auth: when both username and password are non-empty the server rejects unauthenticated requests with 401; either field empty leaves the endpoint open. The credentials travel inside the TLS tunnel, never in clear.

Wire format

A request body of {"topic": "...", "data": { ... }} rebuilds a message with that topic and that data bag verbatim. Optional id and created string fields are also restored onto the envelope. When the body has no data wrapper the whole top-level object becomes the data bag, so a flat {"foo": 1} from an ad-hoc client lands as data.foo = 1.

A successful POST returns 200 OK with a one-line {"ok":true} body. Malformed JSON or a non-object root returns 400. GET / returns a plain-text banner so an operator can probe liveness without constructing a JSON body.

PropertyDescription
port TCP port to listen on; 0 disables the server. Defaults to 8443. Pipnode runs unprivileged, so binding the standard 443 requires either running as root or setting CAP_NET_BIND_SERVICE on the binary.
username HTTP Basic auth username; empty leaves the endpoint open.
password HTTP Basic auth password; empty leaves the endpoint open.
cert-path Path to a PEM-encoded TLS certificate. Defaults to $XDG_DATA_HOME/pipnode/default-cert.pem; the file is minted lazily on the first start and reused on every run after that. Point at a different file to swap in a real cert. Clearing both this and key-path falls back to an ephemeral, in-memory self-signed cert.
key-path Path to the PEM-encoded private key matching cert-path. Defaults to $XDG_DATA_HOME/pipnode/default-key.pem, generated together with the certificate and stored chmod 0600.
Quick test
curl -k -X POST https://localhost:8443/ \
     -H 'Content-Type: application/json' \
     -d '{"topic": "demo", "data": {"hello": "world"}}'

If the node is configured with credentials, add -u user:pass.
