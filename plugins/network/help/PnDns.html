DNS Check

Group: Network. Type: PnDns.

Auto-triggered probe that asks a DNS server to resolve a list of names every period seconds and emits an aggregate result. The probe spawns the system dig utility on a worker thread; per-query timeout is derived from the period so an unreachable server cannot stall ticks.

The point of this node is to verify the DNS server itself, so the probe is a pure DNS query — /etc/hosts, mDNS and NSS are deliberately bypassed. A short name that only lives in /etc/hosts will therefore look like a failed lookup, which is the intended behaviour: if the DNS server doesn't know it, the node says so.

The server property is optional. When empty the resolvers from /etc/resolv.conf are queried; set it to test a specific server (e.g. 8.8.8.8, an internal recursor). The names property is a whitespace- or comma-separated list of names to look up on every tick. While it is empty the node turns red, shows a warning glyph, and skips its triggers entirely.

The emitted message carries data.success (true only when every name resolved), data.output (one-line summary), data.server (the configured server, or "system" when the system resolver was used), data.ok_count / data.name_count, and a data.results object mapping each queried name to a boolean.

PropertyDescription
server DNS server to query (hostname or IP). Optional — when empty the resolvers from /etc/resolv.conf are queried directly via dig (still pure DNS, no /etc/hosts fallback).
names Whitespace- or comma-separated list of DNS names to look up. Required.
period Seconds between probes.
