Tmux Monitor

Group: Shell. Type: PnTmuxMonitor.

Auto-triggered runner that captures the visible characters of a named tmux session every period seconds and emits them on its output port. The capture is performed by spawning tmux capture-pane -p -T -S -<line-limit> -t <session> (-T drops trailing blank positions so lines are not padded out to the pane width) on a worker thread, so the GUI never blocks even when the configured host is slow to respond over ssh. -T only trims trailing blank columns; the empty rows at the bottom of the pane have no capture-pane switch to suppress them, so the node strips those trailing blank lines itself before emitting.

The emitted message (topic tmux) carries:

  • data.success — true when tmux capture-pane exited with status 0, false otherwise (e.g. the session no longer exists, the tmux server stopped, the ssh hop failed).
  • data.output — only the new lines since the previous successful capture. tmux capture-pane re-emits the whole visible pane on every run, so the node keeps the previous tick's text and computes the longest line-wise overlap between the two; whatever lies past that overlap is the genuine new tail and is what the message carries. When the panes share no overlap (the user cleared the screen, the session was switched in tmux, etc.) the full new capture is emitted instead, so a downstream consumer never has to re-derive the missing history itself. When the buffer is unchanged since the previous tick the new tail is empty and the node stays silent — no message is emitted while the monitored screen sits idle. Multi-line text survives the JSON envelope unchanged (embedded newlines escape as \n on the wire). A failed capture (spawn refused, ssh down, tmux exited non-zero) is emitted verbatim and does not overwrite the baseline, so the next successful capture diffs against the last good one.
  • data.host — the host the capture ran on (the local machine’s real name when the host is left empty or set to a local synonym).
  • data.session — the session name the capture targeted.

The settings dialog populates the Session row as a combobox. The list is refreshed by a one-shot enumerator thread that runs tmux list-sessions -F '#S' against the configured host whenever host changes (and once at node construction time, so the combo arrives already populated for a fresh node on the local machine). While the enumerator is in flight the host overlays its standard "busy" spinner on top of the form and locks editing — the same overlay that #PnMeshtastic uses while it opens a serial device. A red status row below the form surfaces the failure reason when the most recent enumeration did not succeed:

  • Cannot run tmux on host: … — the spawn itself failed (ssh refused the connection, the binary is not on PATH, etc.).
  • host: no server running on /tmp/tmux-N/default — tmux is installed but no server is currently active on the host.
  • No tmux sessions on host. — tmux exited cleanly but the server has no sessions.

While tmux-session is empty the node turns red, shows a warning glyph, and skips its triggers entirely (the periodic worker still wakes, it just has no target to capture from).

The remote login defaults to your ambient SSH setup: the local desktop account and whatever key your ssh-agent or ~/.ssh already provides, trusting the host key on first sight. To reach the host as a different account, on a non-standard port, with a specific identity file, or under a stricter host-key policy, attach an SSH Login credential from the node's SSH Login picker (the auth-profile property). The credential says how to log in; the host field still says where. With none selected the node keeps the original passwordless-SSH behaviour.

PropertyDescription
host Where to run the tmux commands. Default: the empty string — the local machine, whose name appears as a grey hint in the settings entry. An empty value, localhost, 127.0.0.1 and ::1 all run locally (clearing the field leaves it empty rather than reverting to localhost). Any other value (a hostname or user@host) routes the run through ssh -o BatchMode=yes -o ConnectTimeout=5; a working passwordless key for that host is required since BatchMode disables every interactive prompt.
tmux-session Name of the session to capture from. Picked from the combobox the enumerator fills; an empty value puts the node in the warning state and stops its triggers. Changing host clears the selection, since a session on one host does not carry over to another.
line-limit Maximum number of trailing lines to capture per tick, passed straight to tmux capture-pane as -S -<N>. Default 50.
period Seconds between captures.
auth-profile Optional SSH Login credential supplying the remote account, port, identity file and host-key policy. Empty (the default) follows the primary SSH Login profile, or — when none is configured — the node's ambient-key behaviour. Stored in the host vault, never in the worksheet file. Separate from host, which still selects where to connect.
