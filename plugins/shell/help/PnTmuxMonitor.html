Tmux Monitor

Group: Shell. Type: PnTmuxMonitor.

Auto-triggered runner that captures the visible characters of a named tmux session every period seconds and emits them on its output port. The capture is performed by spawning tmux capture-pane -p -S -<line-limit> -t <session> on a worker thread, so the GUI never blocks even when the configured host is slow to respond over ssh.

The emitted message (topic tmux) carries:

  • data.success — true when tmux capture-pane exited with status 0, false otherwise (e.g. the session no longer exists, the tmux server stopped, the ssh hop failed).
  • data.output — only the new lines since the previous successful capture. tmux capture-pane re-emits the whole visible pane on every run, so the node keeps the previous tick's text and computes the longest line-wise overlap between the two; whatever lies past that overlap is the genuine new tail and is what the message carries. When the panes share no overlap (the user cleared the screen, the session was switched in tmux, etc.) the full new capture is emitted instead, so a downstream consumer never has to re-derive the missing history itself. Multi-line text survives the JSON envelope unchanged (embedded newlines escape as \n on the wire). A failed capture (spawn refused, ssh down, tmux exited non-zero) is emitted verbatim and does not overwrite the baseline, so the next successful capture diffs against the last good one.
  • data.host — the host the capture ran on (localhost for the local synonyms).
  • data.session — the session name the capture targeted.

The settings dialog populates the Session row as a combobox. The list is refreshed by a one-shot enumerator thread that runs tmux list-sessions -F '#S' against the configured host whenever host changes (and once at node construction time, so the combo arrives already populated for a fresh node on the local machine). While the enumerator is in flight the host overlays its standard "busy" spinner on top of the form and locks editing — the same overlay that #PnMeshtastic uses while it opens a serial device. A red status row below the form surfaces the failure reason when the most recent enumeration did not succeed:

  • Cannot run tmux on host: … — the spawn itself failed (ssh refused the connection, the binary is not on PATH, etc.).
  • host: no server running on /tmp/tmux-N/default — tmux is installed but no server is currently active on the host.
  • No tmux sessions on host. — tmux exited cleanly but the server has no sessions.

While tmux-session is empty the node turns red, shows a warning glyph, and skips its triggers entirely (the periodic worker still wakes, it just has no target to capture from).

PropertyDescription
host Where to run the tmux commands. Default localhost (and the synonyms 127.0.0.1, ::1, empty string) runs locally. Any other value (a hostname or user@host) routes the run through ssh -o BatchMode=yes -o ConnectTimeout=5; a working passwordless key for that host is required since BatchMode disables every interactive prompt.
tmux-session Name of the session to capture from. Picked from the combobox the enumerator fills; an empty value puts the node in the warning state and stops its triggers.
line-limit Maximum number of trailing lines to capture per tick, passed straight to tmux capture-pane as -S -<N>. Default 50.
period Seconds between captures.
