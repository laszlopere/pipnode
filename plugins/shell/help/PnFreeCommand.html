Free Command

Group: Shell. Type: PnFreeCommand.

Auto-triggered runner that executes free every period seconds and emits one message per run on its output port. The command is spawned on a worker thread so the GUI never blocks; free is looked up on PATH.

Unlike Shell Command, the emitted message carries the parsed table inline: free's default output is column-aligned and has a fixed shape (one header line, one Mem: data row, one Swap: data row), so the node just whitespace-splits each line and builds data.table in the standard shape Table View consumes -- no Table Model filter in between.

The emitted message carries:

  • data.success — true when free exited with status 0, false otherwise.
  • data.output — the combined stdout and stderr of the run, verbatim.
  • data.table — the parsed table in the standard { "header": { "cells": [...] }, "rows": [ { "cells": [...] }, ... ] } shape. Each cell is a JSON object with at minimum { "text": "...", "name": "..." }; the Table View sink reads only the text and ignores unknown members, so the extra name is transparent to it.

Cell names follow the shape <row>.<column> so a later consumer can pick a specific cell symbolically. The row part comes from the first column of each data row, sanitised (Mem: → mem, Swap: → swap); the column part comes from the header text, sanitised (buff/cache → buff_cache); the leading row-label column has no header text, so its column id is the literal name, and the header row's row id is the literal header.

With the canonical free output, this produces cell names header.name, header.total, header.used, header.free, header.shared, header.buff_cache, header.available for the header row, and analogous mem.* / swap.* ids for the data rows. Trailing cells that the Swap: line does not produce (swap.shared, swap.buff_cache, swap.available) still appear in the table with an empty text, so a consumer can index by name without guarding against ragged rows.

PropertyDescription
host Where to run free. Default localhost (and the synonyms 127.0.0.1, ::1, empty string) runs locally. Any other value (a hostname or user@host) routes the run through ssh -o BatchMode=yes -o ConnectTimeout=5; a working passwordless key for that host is required since BatchMode disables every interactive prompt.
period Seconds between executions.
