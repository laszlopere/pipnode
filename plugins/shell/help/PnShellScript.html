Shell Script

Group: Shell. Type: PnShellScript.

The multi-line sibling of Shell Command: an auto-triggered runner that executes a whole shell script every period seconds and emits one message per run on its output port. Runtime behaviour is identical to Shell Command — the script is fed to /bin/sh -c on a worker thread so the GUI never blocks on a slow run, and functions, loops, here-documents, pipes, redirections and shell variable expansion all work as they would in a saved .sh file. The only difference is the editor: the settings dialog presents the body in a full-width GtkSourceView code editor with sh syntax highlighting, line numbers and bracket matching, so a longer script reads and edits comfortably.

The emitted message carries:

  • data.success — true when the script exited with status 0, false otherwise.
  • data.output — the combined stdout and stderr of the run, verbatim. JSON serialisation of the message escapes embedded newlines as the standard \n sequence on its own, so the value survives transport as one logical string; a downstream Debug Print node in text mode renders multi-line output across multiple lines.

While shell-script is empty the node turns red, shows a warning glyph, and skips its triggers entirely.

The script may embed the node variables ${nodeclass}, ${nodename}, and ${hostname}, which Pipnode substitutes before the script runs. Any other ${...} is left untouched, so ordinary shell variables such as ${HOME} are still expanded by the shell itself.

The remote login defaults to your ambient SSH setup: the local desktop account and whatever key your ssh-agent or ~/.ssh already provides, trusting the host key on first sight. To reach the host as a different account, on a non-standard port, with a specific identity file, or under a stricter host-key policy, attach an SSH Login credential from the node's SSH Login picker (the auth-profile property). The credential says how to log in; the host field still says where. With none selected the node keeps the original passwordless-SSH behaviour.

PropertyDescription
shell-script Multi-line shell script to execute. Required. Edited in a code editor with sh highlighting. ${nodeclass} / ${nodename} / ${hostname} are substituted; any other ${...} is left for the shell.
host Where to run the script. Default: the empty string — the local machine, whose name appears as a grey hint in the settings entry. An empty value, localhost, 127.0.0.1 and ::1 all run locally (clearing the field leaves it empty rather than reverting to localhost). Any other value (a hostname or user@host) routes the run through ssh -o BatchMode=yes -o ConnectTimeout=5; a working passwordless key for that host is required since BatchMode disables every interactive prompt.
period Seconds between executions.
auth-profile Optional SSH Login credential supplying the remote account, port, identity file and host-key policy. Empty (the default) follows the primary SSH Login profile, or — when none is configured — the node's ambient-key behaviour. Stored in the host vault, never in the worksheet file. Separate from host, which still selects where to connect.
