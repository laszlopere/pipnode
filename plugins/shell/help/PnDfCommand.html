Df Command

Group: Shell. Type: PnDfCommand.

Auto-triggered runner that executes df every period seconds and emits one message per run on its output port. df is looked up on PATH; the command is spawned on a worker thread so the GUI never blocks.

Like Free Command, the emitted message carries the parsed table inline so a downstream Table View can render it without an intermediate Table Model filter. The parser hard-codes the knowledge of df's default output shape (six logical columns, the last of which is the mount path) and just whitespace-splits each line, folding the tail tokens of every line back into the mount-path column so a long mount path (or a header word like "Mounted on" with an internal space, or a mount point like "/mnt/My Documents") stays a single column rather than spilling into a phantom seventh column the way a generic two-pass column-position detector would split it.

The emitted message carries:

  • data.success — true when df exited with status 0, false otherwise.
  • data.output — the combined stdout and stderr of the run, verbatim.
  • data.table — the parsed table in the standard { "header": { "cells": [...] }, "rows": [ { "cells": [...] }, ... ] } shape. Each cell is a JSON object with at minimum { "text": "...", "name": "..." }; the Table View sink reads only text and ignores unknown members, so the extra name is transparent to it.

Cell names follow the shape <row>.<column>. The column id comes from the sanitised header text ("Filesystem" → filesystem, "1K-blocks" → 1k_blocks, "Use%" → use, "Mounted on" → mounted_on); the row id comes from the sanitised first-column value ("/dev/nvme0n1p2" → dev_nvme0n1p2, "tmpfs" → tmpfs), with leading and trailing underscores stripped so a path-rooted identifier doesn't read as _dev_…. The header row's row id is the literal header.

The remote login defaults to your ambient SSH setup: the local desktop account and whatever key your ssh-agent or ~/.ssh already provides, trusting the host key on first sight. To reach the host as a different account, on a non-standard port, with a specific identity file, or under a stricter host-key policy, attach an SSH Login credential from the node's SSH Login picker (the auth-profile property). The credential says how to log in; the host field still says where. With none selected the node keeps the original passwordless-SSH behaviour.

PropertyDescription
host Where to run df. Default: the empty string — the local machine, whose name appears as a grey hint in the settings entry. An empty value, localhost, 127.0.0.1 and ::1 all run locally (clearing the field leaves it empty rather than reverting to localhost). Any other value (a hostname or user@host) routes the run through ssh -o BatchMode=yes -o ConnectTimeout=5; a working passwordless key for that host is required since BatchMode disables every interactive prompt.
period Seconds between executions.
auth-profile Optional SSH Login credential supplying the remote account, port, identity file and host-key policy. Empty (the default) follows the primary SSH Login profile, or — when none is configured — the node's ambient-key behaviour. Stored in the host vault, never in the worksheet file. Separate from host, which still selects where to connect.
