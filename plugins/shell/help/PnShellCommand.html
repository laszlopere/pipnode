Shell Command

Group: Shell. Type: PnShellCommand.

Auto-triggered runner that executes the configured one-line shell command every period seconds and emits one message per run on its output port. The command is spawned via /bin/sh -c on a worker thread so the GUI never blocks on slow commands; pipes, redirections, and shell variable expansion all work as they would on the terminal.

The emitted message carries:

  • data.success — true when the command exited with status 0, false otherwise.
  • data.output — the combined stdout and stderr of the run, verbatim. JSON serialisation of the message escapes embedded newlines as the standard \n sequence on its own, so the value survives transport as one logical string; downstream Debug Print nodes in text mode render the raw bytes (i.e. multi-line output prints across multiple lines).

While shell-command is empty the node turns red, shows a warning glyph, and skips its triggers entirely.

The command may embed the node variables ${nodeclass}, ${nodename}, and ${hostname}, which Pipnode substitutes before the command runs — for example ssh ${hostname} uptime. Any other ${...} is left untouched, so ordinary shell variables such as ${HOME} are still expanded by the shell itself.

The remote login defaults to your ambient SSH setup: the local desktop account and whatever key your ssh-agent or ~/.ssh already provides, trusting the host key on first sight. To reach the host as a different account, on a non-standard port, with a specific identity file, or under a stricter host-key policy, attach an SSH Login credential from the node's SSH Login picker (the auth-profile property). The credential says how to log in; the host field still says where. With none selected the node keeps the original passwordless-SSH behaviour.

PropertyDescription
shell-command One-line shell command to execute. Required. ${nodeclass} / ${nodename} / ${hostname} are substituted; any other ${...} is left for the shell.
host Where to run the command. Default: the empty string — the local machine, whose name appears as a grey hint in the settings entry. An empty value, localhost, 127.0.0.1 and ::1 all run locally (clearing the field leaves it empty rather than reverting to localhost). Any other value (a hostname or user@host) routes the run through ssh -o BatchMode=yes -o ConnectTimeout=5; a working passwordless key for that host is required since BatchMode disables every interactive prompt.
period Seconds between executions.
auth-profile Optional SSH Login credential supplying the remote account, port, identity file and host-key policy. Empty (the default) follows the primary SSH Login profile, or — when none is configured — the node's ambient-key behaviour. Stored in the host vault, never in the worksheet file. Separate from host, which still selects where to connect.
